### Dockerfile Structure and Build Process
The [`/mmb-irb/mddb-workflow/docker/Dockerfile`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile) defines the build process for creating a Docker image that encapsulates the [`MDDB-workflow`](https://github.com/mmb-irb/mddb-workflow/README.md#L4) environment, ensuring consistent and reproducible execution across various computing environments.

The Docker build process begins by cloning the entire [`MDDB-workflow`](https://github.com/mmb-irb/mddb-workflow/README.md#L4) repository into the image. Subsequently, a dedicated Miniconda3 environment, named [`mwf_env`](https://github.com/mmb-irb/mddb-workflow/README.md#L28), is established within the container. This environment is configured based on the [`environment.yml`](https://github.com/mmb-irb/mddb-workflow/README.md#L17) file located within the cloned repository, which specifies all necessary dependencies for the workflow. Following the environment setup, the [`MDDB-workflow`](https://github.com/mmb-irb/mddb-workflow/README.md#L4) software itself is installed into this [`mwf_env`](https://github.com/mmb-irb/mddb-workflow/README.md#L28) environment, enabling the execution of its components.

To facilitate seamless operation within the container, the [`/mmb-irb/mddb-workflow/docker/Dockerfile`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile) also extends the [`PYTHONPATH`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile#L31) to ensure Python can correctly locate all [`MDDB-workflow`](https://github.com/mmb-irb/mddb-workflow/README.md#L4) modules. A key aspect of the container's design is the generation of an [`entrypoint.sh`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile#L34) script. This script serves as the primary execution point for the Docker container, utilizing [`conda run`](https://github.com/mmb-irb/mddb-workflow/README.md#L41) to activate the [`mwf_env`](https://github.com/mmb-irb/mddb-workflow/README.md#L28) and execute workflow commands in a properly isolated environment. The [`entrypoint.sh`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile#L34) script is then set as the [`ENTRYPOINT`](https://github.com/mmb-irb/mddb-workflow/docker/Dockerfile#L39) for the Docker image, dictating the command that will be executed when the container starts.

For a deeper understanding of how this entrypoint script functions during container execution, refer to [Entrypoint Script and Container Execution](#containerized-workflow-execution-entrypoint-script-and-container-execution).
