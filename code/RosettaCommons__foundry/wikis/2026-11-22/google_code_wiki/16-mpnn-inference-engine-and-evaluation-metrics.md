### MPNN Inference Engine and Evaluation Metrics
The MPNN inference engine orchestrates the entire process of sequence design using ProteinMPNN and LigandMPNN models. The core component, the [`MPNNInferenceEngine`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py#L38) class located in [`/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py), is responsible for initializing the engine, configuring model parameters and output settings, and managing the execution of inference runs. It validates configurations such as [`model_type`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L26), [`checkpoint_path`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference.py#L31), and [`out_directory`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L176) to ensure proper setup.

Model loading is a key function, where [`MPNNInferenceEngine`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py#L38) builds and loads the appropriate [`ProteinMPNN`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L21) or [`LigandMPNN`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L2303) model. It supports both standard and legacy checkpoint formats, with older weights undergoing a series of transformations to adapt to the current model implementation. These transformations, handled by [`load_legacy_weights`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py#L20) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py), involve renaming parameters, adjusting atom type embeddings, and reordering backbone distance and amino acid token embeddings to ensure compatibility. The system also handles the detection of available hardware accelerators (CUDA, XPU, MPS), falling back to CPU if none are present to ensure broad compatibility.

During inference, the [`MPNNInferenceEngine`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py#L38) processes input structures, batching them and applying a transformation pipeline to convert raw structural data into features suitable for the model. After the model's forward pass, predicted sequences are decoded from the model's output. The designed sequences, along with per-residue confidence scores, are then used to update the input [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) objects. Side-chain atoms that are no longer relevant to the redesigned sequence are removed, retaining only backbone and fixed atoms.

Evaluation metrics provide crucial insights into the model's performance and the quality of designed sequences. The metrics are defined in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics) and include:
*   **Negative Log Likelihood (NLL)** and **Perplexity**: The [`NLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L14) class in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py) calculates these metrics based on ground truth sequences and predicted log probabilities. Specialized versions like [`InterfaceNLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L222) compute these specifically for residues at the polymer-ligand interface, identified dynamically using distance thresholds and atom arrays.
*   **Confidence Scores**: [`MPNNConfidence`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L495) and [`MPNNLigandInterfaceConfidence`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L539) derive confidence scores from sampled sequence NLL, indicating the model's certainty in its predictions, both generally and for interface residues.
*   **Sequence Recovery**: The [`SequenceRecovery`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py#L14) class in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py) measures the percentage of correctly predicted residues by comparing sampled and argmax sequences against ground truth. [`InterfaceSequenceRecovery`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py#L294) extends this to evaluate recovery specifically within protein-ligand interface regions.

The CLI utilities in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py) provide a user-friendly interface for initiating inference runs. They manage argument parsing, JSON configuration loading, and the creation of structured [`MPNNInferenceInput`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L681) objects. These objects encapsulate [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) data along with inference parameters, including detailed specifications for design scope (e.g., fixed or designed residues/chains), bias settings, temperature, and symmetry constraints. After inference, results are stored in [`MPNNInferenceOutput`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L2206) objects, which can then be used to write designed structures as CIF files and sequences as FASTA files, complete with metadata. The system ensures robust error handling and configuration validation throughout the process.
