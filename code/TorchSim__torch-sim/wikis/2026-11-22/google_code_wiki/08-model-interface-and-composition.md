### Model Interface and Composition
The [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) within [`/torchsim/torch-sim/torch_sim/models/interface.py`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py) establishes a foundational contract for all models that calculate energies, forces, and stresses in atomistic simulations. This abstract base class, derived from [`torch.nn.Module`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71), requires concrete model implementations to provide a [`forward`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L84) method that accepts a [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) object and returns a dictionary containing [`"energy"`](https://github.com/torchsim/torch-sim/torch_sim/units.py#L104), [`"forces"`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L904), and optionally [`"stress"`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L905) tensors. It also mandates properties such as [`device`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L418), [`dtype`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L423), [`compute_stress`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L135), and [`compute_forces`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L147), ensuring consistency in how models interact with the simulation framework.

To facilitate the construction of complex potential energy surfaces, [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) provides mechanisms for combining multiple models. The [`SumModel`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L204) class, also defined in [`/torchsim/torch-sim/torch_sim/models/interface.py`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py), enables the additive composition of child models. When its [`forward`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L84) method is called, it iteratively invokes the [`forward`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L84) method of each child model, summing their canonical mechanical outputs (energy, forces, and stress) into a combined result. Non-canonical outputs from later models in the composition overwrite those from earlier models, following a specific accumulation logic. This design allows for modular development and flexible combination of different interaction types. Building on this, the [`SerialSumModel`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L325) in the same file extends the composition capability by passing an updated [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) to subsequent models in the series. This allows models positioned later in the chain to utilize features or modifications introduced by preceding models, supporting more intricate, sequential processing workflows where one model's output influences the input of the next.

Ensuring the correctness and physical adherence of model implementations is crucial. The [`validate_model_outputs`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L387) utility function, found in [`/torchsim/torch-sim/torch_sim/models/interface.py`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py), plays a vital role in this. It rigorously tests [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) implementations against various scenarios, including single and multi-batch systems, and both periodic and non-periodic boundary conditions. This function verifies the presence and correct format of output tensors, checks for non-mutation of the input [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121), and validates that outputs behave as expected under fundamental physical principles, such as consistency during periodic translations. This comprehensive validation process helps guarantee that models conform to the framework's expectations and produce physically sensible results.
