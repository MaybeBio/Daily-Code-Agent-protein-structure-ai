### Training Utilities: EMA, Checkpointing, and Schedulers
The Foundry framework integrates several utilities to enhance and stabilize the training process, complementing the core [`FabricTrainer`](https://github.com/rosettacommons/foundry/src/foundry/trainers/fabric.py#L56) [Training Harness with PyTorch Lightning Fabric](#foundry-core-library-and-ml-workflows-training-harness-with-pytorch-lightning-fabric). These utilities focus on improving model generalization, optimizing memory usage, and providing flexible control over the learning rate schedule.

For instance, the Exponential Moving Average (EMA) is implemented in the [`EMA`](https://github.com/rosettacommons/foundry/src/foundry/training/EMA.py#L9) class within [`/rosettacommons/foundry/src/foundry/training/EMA.py`](https://github.com/rosettacommons/foundry/src/foundry/training/EMA.py). This mechanism maintains a "shadow" copy of the model's parameters, which are updated as an exponential moving average of the actively trained model's weights. During inference, the shadow model can be used instead of the primary model, often leading to more stable and better-generalizing predictions by smoothing out rapid fluctuations in weights during training.

Gradient checkpointing, a technique to reduce memory consumption during training, is facilitated by utilities in [`/rosettacommons/foundry/src/foundry/training/checkpoint.py`](https://github.com/rosettacommons/foundry/src/foundry/training/checkpoint.py). The [`create_custom_forward`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/util_module.py#L33) function addresses a limitation in PyTorch's native [`checkpoint`](https://github.com/rosettacommons/foundry/models/rfd3/docs/tutorials/RFdiffusion3_installation_tutorial.md#L258) function, allowing keyword arguments to be passed to checkpointed modules. This enables a wider range of neural network architectures to benefit from memory savings. The [`activation_checkpointing`](https://github.com/rosettacommons/foundry/src/foundry/training/checkpoint.py#L38) decorator provides a convenient way to apply this technique to a function's forward pass, conditionally wrapping it with gradient checkpointing only when gradients are enabled.

Learning rate control is managed through schedulers, particularly the [`AF3Scheduler`](https://github.com/rosettacommons/foundry/src/foundry/training/schedulers.py#L7) defined in [`/rosettacommons/foundry/src/foundry/training/schedulers.py`](https://github.com/rosettacommons/foundry/src/foundry/training/schedulers.py). This scheduler implements a two-phase learning rate schedule: an initial linear warmup phase where the learning rate gradually increases, followed by a decay phase where it decreases over time. This approach is common in deep learning to ensure stable convergence and prevent premature overfitting. Additionally, the [`SchedulerConfig`](https://github.com/rosettacommons/foundry/src/foundry/training/schedulers.py#L66) dataclass provides a standardized way to configure any learning rate scheduler, specifying how often it should be applied (per step or per epoch) and allowing for serialization and deserialization of its state.
