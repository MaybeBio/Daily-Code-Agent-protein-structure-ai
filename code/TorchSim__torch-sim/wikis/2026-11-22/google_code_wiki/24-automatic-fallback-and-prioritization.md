### Automatic Fallback and Prioritization
The [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) library provides a robust mechanism for automatically selecting the most efficient neighbor list algorithm available on a given system. This ensures optimal performance across diverse hardware configurations without requiring manual intervention from the user. The core logic for this selection resides within the [`torchsim_nl`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/__init__.py#L46) function in [`/torchsim/torch-sim/torch_sim/neighbors/__init__.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/__init__.py).

The selection process follows a prioritized order:

1.  **Alchemiops**: The system first attempts to utilize NVIDIA's [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) library, which offers highly optimized, GPU-accelerated N² or cell-list neighbor searches. If [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) is detected and available, the [`alchemiops_nl_n2`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/alchemiops.py#L35) implementation in [`/torchsim/torch-sim/torch_sim/neighbors/alchemiops.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/alchemiops.py) is chosen. This provides significant performance gains on compatible NVIDIA GPUs.

2.  **Vesin**: If Alchemiops is not available, the system checks for the [`vesin`](https://github.com/torchsim/torch-sim/pyproject.toml#L50) library. Two implementations are considered:
    *   **TorchScript-optimized Vesin**: If a TorchScript-compatible version of [`vesin`](https://github.com/torchsim/torch-sim/pyproject.toml#L50) is installed, [`vesin_nl_ts`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/vesin.py#L184) in [`/torchsim/torch-sim/torch_sim/neighbors/vesin.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/vesin.py) is prioritized. This version offers improved performance through TorchScript optimization.
    *   **Standard Vesin**: If the TorchScript version is not available, the standard [`vesin_nl`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/vesin.py#L36) implementation, also in [`/torchsim/torch-sim/torch_sim/neighbors/vesin.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/vesin.py), is used. The [`vesin`](https://github.com/torchsim/torch-sim/pyproject.toml#L50) library provides efficient neighbor list generation for various hardware.

3.  **Pure PyTorch**: As a final fallback, if neither Alchemiops nor Vesin implementations are found, [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) defaults to a pure PyTorch solution. The [`torch_nl_linked_cell`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/torch_nl.py#L156) function in [`/torchsim/torch-sim/torch_sim/neighbors/torch_nl.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/torch_nl.py) implements an O(N) linked-cell algorithm, which is generally efficient for larger systems. For smaller systems or specific debugging scenarios, an O(N²) brute-force [`torch_nl_n2`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/torch_nl.py#L94) is also available as part of the pure PyTorch offerings.

This hierarchical selection ensures that [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) can always compute neighbor lists, adapting to the available software and hardware resources to maximize efficiency. This automated approach simplifies development and deployment, allowing users to focus on simulation science rather than infrastructure specifics. The [`normalize_inputs`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/utils.py#L7) utility in [`/torchsim/torch-sim/torch_sim/neighbors/utils.py`](https://github.com/torchsim/torch-sim/torch_sim/neighbors/utils.py) plays a supporting role by standardizing the input formats for cell and periodic boundary condition tensors, ensuring compatibility across all chosen neighbor list implementations.
