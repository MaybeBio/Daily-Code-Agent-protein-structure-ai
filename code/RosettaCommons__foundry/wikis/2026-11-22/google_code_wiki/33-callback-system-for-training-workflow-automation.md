### Callback System for Training Workflow Automation
Foundry employs a callback system to enable custom logic injection at various stages of the machine learning training and validation processes. This system is structured around the abstract base class [`BaseCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L9), defined in [`/rosettacommons/foundry/src/foundry/callbacks/callback.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py), which provides a set of hook methods corresponding to different events in the training lifecycle. These hooks allow developers to execute specific actions, such as logging, monitoring, or modifying training behavior, without altering the core training loop. Each hook typically provides access to the [`trainer`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L287) object, allowing interaction with the training state and underlying [`lightning.fabric`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L84) components.

Specific implementations of these callbacks address different aspects of training automation:

Model health tracking is handled by the [`ActivationsGradientsWeightsTracker`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/health_logging.py#L48) in [`/rosettacommons/foundry/src/foundry/callbacks/health_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/health_logging.py). This callback monitors the behavior of a neural network by collecting statistics on its activations, gradients, and weights. It uses hooks to register and remove forward pass captures and iterates through model parameters to gather metrics such as mean, standard deviation, and norm. These statistics can be logged as scalars or histograms, providing insights into model stability and training progression.

For managing validation metrics, the [`StoreValidationMetricsInDFCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py#L16) in [`/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py) collects and aggregates validation results. In distributed training environments, each process accumulates its own metrics into a DataFrame and saves it to a temporary file. The global rank zero then gathers these files, concatenates them, and stores the combined results, handling potential data duplication. This ensures a consolidated view of validation performance across all distributed nodes.

Performance profiling during training is facilitated by the [`TimingCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L13) in [`/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py). This callback measures the duration of various training phases, such as data loading, forward and backward passes, and optimizer steps. It uses an internal [`Timers`](https://github.com/rosettacommons/foundry/src/foundry/utils/torch.py#L330) object to track these durations and reports average timings at configurable intervals, providing insight into where computational resources are being spent.

Comprehensive training progress logging is implemented through several callbacks within [`/rosettacommons/foundry/src/foundry/callbacks/train_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/train_logging.py). These include callbacks to log the number of model parameters, display example IDs for debugging, monitor dataset sampling ratios, track learning rates, and provide detailed breakdowns of training losses. These callbacks contribute to a rich console output, offering a clear overview of the training process and resource utilization.
