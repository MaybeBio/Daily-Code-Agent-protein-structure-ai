### RFD3NA Training Pipeline and Metrics
The RFD3NA training process leverages [`hydra`](https://github.com/rosettacommons/foundry/pyproject.toml#L27) for flexible configuration management and [`lightning.fabric`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L84) to enable distributed training across multiple GPUs. The primary entry point for initiating training is the [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/train.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/train.py) script, which orchestrates the entire workflow from configuration loading to model execution.

The core training logic is encapsulated within the [`AADesignTrainer`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L33), defined in [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/rfd3na.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/rfd3na.py). This specialized trainer extends the generic [`FabricTrainer`](https://github.com/rosettacommons/foundry/src/foundry/trainers/fabric.py#L56) (see [Training Harness with PyTorch Lightning Fabric](#foundry-core-library-and-ml-workflows-training-harness-with-pytorch-lightning-fabric)) to handle the unique aspects of multipolymer design. It manages the assembly of network inputs, the computation of losses during the [`training_step`](https://github.com/rosettacommons/foundry/src/foundry/trainers/fabric.py#L661), and the evaluation of model performance during the [`validation_step`](https://github.com/rosettacommons/foundry/src/foundry/trainers/fabric.py#L681). During training, the [`AADesignTrainer`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L33) uses a recycling schedule generated by the [`get_recycle_schedule`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/utils/recycling.py#L7) function in [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/recycling.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/recycling.py) to ensure consistent computational intensity across batches and GPUs. This schedule helps in robustly training diffusion models by varying the number of refinement iterations.

A comprehensive suite of metrics and loss functions guides and evaluates the model's learning. The [`Loss`](https://github.com/rosettacommons/foundry/src/foundry/metrics/losses.py#L8) class (see [Loss Function Aggregation with the Loss Class](#model-evaluation-metrics-and-loss-functions-loss-function-aggregation-with-the-loss-class)), integrated into the [`AADesignTrainer`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L33), supports various loss components, including [`SequenceLoss`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/metrics/losses.py#L7) and [`DiffusionLoss`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/loss/af3_losses.py#L416), which can incorporate [`smoothed_lddt_loss`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/loss/af3_losses.py#L544) for structural accuracy. During validation, the model's tensor outputs are transformed into [`AtomArrayStack`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L13) objects using utilities such as [`_build_atom_array_stack`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/trainer_utils.py#L69) from [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/trainer_utils.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/trainer_utils.py). These structured outputs are then evaluated using a rich set of metrics found in [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics). These metrics include detailed design quality assessments like clash detection, chain break analysis, and backbone metrics from [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/design_metrics.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/design_metrics.py). For nucleic acid designs, specialized metrics like F1 scores for secondary structure similarity are calculated using [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/nucleic_ss_metrics.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/nucleic_ss_metrics.py). Hydrogen bond metrics from [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/hbonds_metrics.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/hbonds_metrics.py) and [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/hbonds_hbplus_metrics.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/hbonds_hbplus_metrics.py), along with ligand contact metrics from [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/rna_aptamer_metrics.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/metrics/rna_aptamer_metrics.py), are also employed to provide a holistic view of the designed multipolymer structures. The [`DumpValidationStructuresCallback`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/dump_validation_structures.py#L19) in [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/dump_validation_structures.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/trainer/dump_validation_structures.py) further enhances evaluation by saving predicted structures and associated metadata during validation, allowing for visual inspection and deeper analysis of the design outcomes.
