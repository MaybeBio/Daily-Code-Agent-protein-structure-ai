## Protein Structure Representation and Numerical Operations
Protein structure data within OpenFold is managed through a set of utilities designed for parsing, converting, and representing protein structural information, as detailed in the [`/aqlaboratory/openfold/openfold/np`](https://github.com/aqlaboratory/openfold/openfold/np) directory. This includes core functionality for refining protein coordinates through Amber energy minimization and a centralized system for amino acid properties.

The [`Protein`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L45) dataclass, defined in [`/aqlaboratory/openfold/openfold/np/protein.py`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py), standardizes protein structure representation. This dataclass encapsulates atom positions, amino acid types, masks, residue indices, and B-factors. It provides functionalities for converting between various protein data formats, such as PDB and ModelCIF strings, and for constructing [`Protein`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L45) objects from model predictions. For instance, [`from_pdb_string`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L89) parses PDB strings, while [`to_pdb`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L321) and [`to_modelcif`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L446) convert [`Protein`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L45) objects back into PDB or ModelCIF formats.

Post-prediction refinement of protein structures is handled by the Amber energy minimization process, which uses OpenMM to improve physical realism and reduce steric clashes. This functionality is primarily implemented in the [`/aqlaboratory/openfold/openfold/np/relax`](https://github.com/aqlaboratory/openfold/openfold/np/relax) directory. The [`AmberRelaxation`](https://github.com/aqlaboratory/openfold/openfold/np/relax/relax.py#L23) class in [`/aqlaboratory/openfold/openfold/np/relax/relax.py`](https://github.com/aqlaboratory/openfold/openfold/np/relax/relax.py) orchestrates iterative, restrained Amber energy minimization, configurable with parameters such as maximum iterations, tolerance, and GPU usage. The underlying minimization process, managed by [`run_pipeline`](https://github.com/aqlaboratory/openfold/openfold/np/relax/amber_minimize.py#L475) in [`/aqlaboratory/openfold/openfold/np/relax/amber_minimize.py`](https://github.com/aqlaboratory/openfold/openfold/np/relax/amber_minimize.py), involves cleaning the protein, applying harmonic positional restraints, running OpenMM's energy minimization, and iteratively refining the structure based on detected violations. Structural violations are identified using functions like [`get_violation_metrics`](https://github.com/aqlaboratory/openfold/openfold/np/relax/amber_minimize.py#L399), which help guide the relaxation by adjusting restraints. PDB cleanup utilities, found in [`/aqlaboratory/openfold/openfold/np/relax/cleanup.py`](https://github.com/aqlaboratory/openfold/openfold/np/relax/cleanup.py), leverage [`pdbfixer`](https://github.com/aqlaboratory/openfold/environment.yml#L14) to address common PDB issues, such as nonstandard residues and missing atoms, and also include custom fixes for specific structural anomalies. Utility functions in [`/aqlaboratory/openfold/openfold/np/relax/utils.py`](https://github.com/aqlaboratory/openfold/openfold/np/relax/utils.py) support these operations by overwriting PDB coordinates and B-factors, and validating atom types.

Amino acid properties, atomic structures, and bond geometry constants are centralized in [`/aqlaboratory/openfold/openfold/np/residue_constants.py`](https://github.com/aqlaboratory/openfold/openfold/np/residue_constants.py). This file stores data for all standard amino acid types and provides utility functions for converting sequences to one-hot encodings and for managing rigid group transformations. It precomputes mappings and relative positions for atoms within different rigid groups of each residue type, which are crucial for geometric calculations. It also defines methods to compute lower and upper bounds for inter-atomic distances, essential for assessing steric clashes and bond length violations.

Fundamental mathematical and computational utilities for handling 3D geometric operations, rotations, and rigid body transformations are provided within the [`/aqlaboratory/openfold/openfold/utils/geometry`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry) directory. This module offers core data structures such as [`Vec3Array`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/vector.py#L25) for 3D vectors, [`Rot3Array`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/rotation_matrix.py#L30) for rotation matrices, and [`Rigid3Array`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/rigid_matrix_vector.py#L30) for rigid transformations, enabling operations like composition, inversion, and point application. The [`QuatRigid`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/quat_rigid.py#L10) module in [`/aqlaboratory/openfold/openfold/utils/geometry/quat_rigid.py`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/quat_rigid.py) translates neural network activations into [`Rigid3Array`](https://github.com/aqlaboratory/openfold/openfold/utils/geometry/rigid_matrix_vector.py#L30) transformations using quaternion representations for rotation, providing a differentiable interface between model outputs and geometric transformations. This allows for seamless integration of predicted values into structural representations. For further details on these core geometric data structures, refer to [Core 3D Geometric Data Structures and Operations](#protein-structure-representation-and-numerical-operations-core-3d-geometric-data-structures-and-operations).
