## Inference Engines and Model Execution
The [`/rosettacommons/foundry/src/foundry/inference_engines`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines) directory forms the foundation for managing model setup, configuration, and checkpoint loading for inference within the Foundry ecosystem. This framework simplifies the complexities of model instantiation and execution, providing a consistent interface for various biomolecular design models.

The [`BaseInferenceEngine`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines/base.py#L33) class, located in [`/rosettacommons/foundry/src/foundry/inference_engines/base.py`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines/base.py), serves as the core abstraction. It handles tasks such as resolving and loading model checkpoints, applying configuration overrides using tools like Hydra and OmegaConf, and setting up the model's data transformation pipeline and trainer components. This design ensures that resource-intensive setup operations are performed efficiently, separate from the actual inference runs. The engine supports flexible configuration merging, allowing for dynamic adjustments to model behavior and inference parameters. Additionally, it provides built-in support for distributed inference setups, leveraging parameters like [`num_nodes`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L78) and [`devices_per_node`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L79).

A crucial aspect of the inference engine is its robust checkpoint management system, detailed in [`/rosettacommons/foundry/src/foundry/inference_engines/checkpoint_registry.py`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines/checkpoint_registry.py). This system resolves checkpoint file paths by prioritizing environment variables ([`FOUNDRY_CHECKPOINT_DIRS`](https://github.com/rosettacommons/foundry/.env#L63)), falling back to a default user directory, and includes mechanisms for persisting these configurations in [`.env`](https://github.com/rosettacommons/foundry/.env#L2) files. The [`RegisteredCheckpoint`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines/checkpoint_registry.py#L65) dataclass and the [`REGISTERED_CHECKPOINTS`](https://github.com/rosettacommons/foundry/src/foundry/inference_engines/checkpoint_registry.py#L80) dictionary provide a centralized registry for known model checkpoints, simplifying their identification and location. This allows users to reference common models by mnemonic names, streamlining the workflow for loading and executing inference with established Foundry models.
