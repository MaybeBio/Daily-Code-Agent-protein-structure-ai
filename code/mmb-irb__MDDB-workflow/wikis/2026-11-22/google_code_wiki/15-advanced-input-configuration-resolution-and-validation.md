### Advanced Input Configuration Resolution and Validation
The system manages and validates project input configurations through a sophisticated process that ensures data integrity and consistency across various sources. This is primarily handled by the [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class, which is responsible for loading, merging, and resolving input values, supporting both declarative file-based configurations and dynamic command-line overrides.

Project input configurations are defined using Pydantic schemas, specified in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py). These schemas provide robust validation for various aspects of the workflow, including ligand definitions, interaction parameters, and simulation metadata. For example, the [`Ligand`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py#L35) schema includes validators to expand shorthand notations for PubChem IDs and ensure that at least one database accession is provided. The [`WorkflowInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py#L122) schema, which is the main schema for the entire input file, incorporates field validators for specific parameters like [`orientation`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py#L167), [`framestep`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py#L149), and [`pdb_ids`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/mwf.py#L2212), ensuring they conform to expected formats and constraints. This schema-driven validation helps to catch malformed inputs early in the workflow, preventing errors downstream.

The [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py) orchestrates the input process, beginning with the lazy loading and validation of the project's input document from a file (e.g., [`inputs.yaml`](https://github.com/mmb-irb/mddb-workflow/test/conftest.py#L90) or [`inputs.json`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/utils/constants.py#L67)). It supports [`$DIR`](https://github.com/mmb-irb/mddb-workflow/test/unittests/test_project_inputs.py#L23) replacements to enable relative pathing within the input files and includes legacy fixes for deprecated fields to maintain backward compatibility. Command-line [`forced_inputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/mwf.py#L1372) are normalized and applied, taking precedence over file-based inputs. When retrieving an input value, the system follows a clear precedence order: command-line overrides first, then values from the input file, followed by any explicit defaults provided, and finally, workflow-defined default values.

A key aspect of this input management is handling Molecular Dynamics (MD) specific configurations. The [`merge_md_config`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L195) method within [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) is designed to process MD configurations from various sources, including command-line arguments and glob patterns, allowing for flexible specification of multiple MD replicas. This method ensures that MD configurations are correctly merged and can be distinguished by whether they are topology or structure-based, according to supported formats. The [`validate_md_config`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L309) method further ensures the uniqueness of MD configurations by autofilling missing names or directories and raising an [`InputError`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/utils/auxiliar.py#L45) if duplicate entries are detected after autofilling, thereby maintaining data integrity for MD-specific parameters.

The system also provides mechanisms for persisting changes back to the input file, allowing for dynamic updates and autofilling of generated values. Input files can be checked for availability and, if necessary, generated from templates. This comprehensive approach to input configuration, validation, and resolution ensures that the workflow operates with well-defined and consistent parameters. For more details on how these validated inputs are then used to manage project and MD datasets, refer to [Project and MD Dataset Persistence and Status Tracking](#project-and-md-dataset-management-project-and-md-dataset-persistence-and-status-tracking).
