### RFD3NA Multipolymer Contig Specification and Input Selection
RFD3NA introduces a flexible [`InputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L112) for defining complex multipolymer designs, enabling users to precisely control the design process from initial input structures to conditioning constraints. The core of this specification is the [`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) mini-language, which extends beyond protein design to encompass nucleic acids. For instance, [`10-10,20-20R,30-30D`](https://github.com/rosettacommons/foundry/models/rfd3na/README.md#L55) specifies a design with a 10-residue protein segment, a 20-residue RNA segment, and a 30-residue DNA segment. This syntax allows for the definition of fixed and designed regions, chain breaks, and the explicit typing of polymer chains as protein, RNA, or DNA. Beyond [`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) definition, the [`InputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L112) manages various other parameters such as [`unindex`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L135) for motif tokens with unknown relative sequence placement, [`length`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L141) constraints for designed regions, and [`ligand`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L142) specification for small molecule interactions.

The [`InputSelection`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/parsing.py#L26) mini-language, detailed in [`/rosettacommons/foundry/models/rfd3na/docs/input.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/input.md), provides a unified way to specify residue and atom selections across different fields within the [`InputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L112). This powerful selection mechanism supports boolean values, contig-style strings, and dictionaries, with shorthand values like [`ALL`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L148), [`TIP`](https://github.com/rosettacommons/foundry/models/rf3/README.md#L77), and [`BKBN`](https://github.com/rosettacommons/foundry/models/rfd3na/README.md#L90) for common selections. It is crucial for defining constraints such as [`select_fixed_atoms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L152) (atoms with fixed coordinates), [`select_unfixed_sequence`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L160) (regions where sequence can change), and various conditioning features like [`select_buried`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L170), [`select_exposed`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L172) for solvent accessibility, and [`select_hbond_donor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L175), [`select_hbond_acceptor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L174) for hydrogen bond specific conditioning.

Beyond basic structural definitions, RFD3NA's input system also supports advanced constraints essential for nucleic acid design. This includes specifying RNA secondary structure using dot-bracket notation, either globally via [`ss_dbn`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md#L48) or for specific regions via [`ss_dbn_dict`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md#L65). Furthermore, fine-grained control over base-pairing is achieved through [`paired_region_list`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md#L91), [`loop_region_list`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md#L92), and [`paired_position_list`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md#L116). The [`DesignInputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L115) class, primarily defined in [`/rosettacommons/foundry/models/rfd3na/src/rfd3na/inference/input_parsing.py`](https://github.com/rosettacommons/foundry/models/rfd3na/src/rfd3na/inference/input_parsing.py), parses and validates these user-defined parameters, translating them into an [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) annotated with relevant features for the downstream diffusion model. This process involves a [`build`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L88) method that orchestrates the construction of the final [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20), including steps like deep copying and reordering atoms, appending ligands, applying symmetry transformations, and setting the origin token. This comprehensive input system, including support for legacy formats via [`LegacySpecification`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L80), ensures robust and flexible control over multipolymer design. For more details on the transformation capabilities and symmetry operations, refer to [RFD3NA Data Transforms and Symmetry Operations](#introduction-to-foundry-models-rfd3na-data-transforms-and-symmetry-operations).
