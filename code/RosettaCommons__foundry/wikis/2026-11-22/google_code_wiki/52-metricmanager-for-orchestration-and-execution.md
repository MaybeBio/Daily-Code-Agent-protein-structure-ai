### MetricManager for Orchestration and Execution
The [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) class, defined in [`/rosettacommons/foundry/src/foundry/metrics/metric.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py), is central to orchestrating the evaluation of machine learning models within Foundry. It streamlines the process of managing, filtering, and executing multiple [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) instances, which are abstract representations of individual evaluation criteria. The manager is responsible for instantiating these metrics from configuration, applying conditional filtering based on tags, executing their computation methods, and aggregating their results into a unified output.

When invoked, the [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) iterates through its collection of [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) objects. For each metric, it first determines if it should be computed based on a tag-based filtering mechanism, which uses [`metrics_tags`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L148) provided in the input [`extra_info`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L46) dictionary. This allows for selective metric computation relevant to specific conditions or data subsets. If a metric is eligible, the manager calls its [`compute_from_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L249) method, which intelligently maps the available input data to the arguments expected by the individual metric's computation logic.

The results from each successfully computed metric are then aggregated. If a metric returns a dictionary, its keys are prefixed with the metric's name to ensure uniqueness and clarity in the final output (e.g., [`my_metric.value`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L60)). If a list is returned, it is stored directly under the metric's name. The manager also includes an [`example_id`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L95) in the final results dictionary for traceability. Error reporting during metric computation is handled using [`error.context`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L164) for structured logging, and the [`raise_errors`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L58) flag at initialization determines whether computation failures lead to exceptions or are gracefully suppressed. The [`MetricInputError`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L36) is a specific exception raised when there are issues with the input data provided to a metric. For more details on defining individual metrics, refer to [Metric Definition and Customization](#model-evaluation-metrics-and-loss-functions-metric-definition-and-customization).
