## Project and MD Dataset Management
The system manages both projects and their individual Molecular Dynamics (MD) replicas through a centralized SQLite database. This database, defined within [`/mmb-irb/mddb-workflow/mddb_workflow/core`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core), tracks the status of each project and MD, including whether it is new, running, or completed. It also stores relevant metadata and messages. A robust distributed filesystem locking mechanism ensures data integrity, preventing conflicts when multiple processes interact with the database, particularly across networked file systems.

The core of this management is handled by the [`Dataset`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L154) class in [`/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py). This class is responsible for adding new projects and MDs to the database, querying their statuses, and updating their states as the workflow progresses. Projects and MDs are uniquely identified by UUIDs, allowing for flexible management even if their directory paths change. The system automatically refreshes the status of running jobs by checking active processes or SLURM job queues, marking them as [`ERROR`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L38) if they are no longer active. This ensures the database accurately reflects the current state of all ongoing simulations.

Beyond status tracking, the system facilitates the generation of configuration files, specifically [`inputs.yaml`](https://github.com/mmb-irb/mddb-workflow/test/conftest.py#L90), using Jinja2 templates and Python generator functions. This allows for standardized and reproducible project setups. The [`Dataset`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L154) class also orchestrates the launching of commands and SLURM job scripts for filtered projects, supporting both sequential and parallel execution.

Input configuration for projects is managed and validated through the [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py). This class handles the loading and merging of input values from various sources, including file-based configurations and command-line overrides. It applies a clear precedence order, ensuring that explicit user inputs take precedence over file configurations, which in turn override default values. Input validation is performed against Pydantic schemas defined in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py), which offers robust, field-specific checks while allowing for forward compatibility with unknown fields. This ensures that all project and MD-specific input parameters are correctly formatted and semantically valid before execution. The [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class also includes sophisticated logic for merging MD-specific configurations, including the resolution of glob patterns for input directories and the validation of unique MD names and directories. This comprehensive approach to data management and input validation is central to maintaining the consistency and reliability of MD simulation projects.
