### Core `SimState` Data Structure and Batched Operations
The [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) dataclass serves as the central data structure within TorchSim for encapsulating atomistic system properties. It stores information such as atomic numbers, cell parameters, and other simulation variables, with all attributes represented as PyTorch tensors. This design is crucial for leveraging PyTorch's capabilities, enabling mathematical operations performed by integrators and optimizers, as well as model forward passes, to act directly on these tensors, thereby optimizing GPU performance.

[`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) supports batched operations, allowing it to represent either a single system or a collection of multiple systems simultaneously. This batched approach is fundamental to TorchSim's efficiency in handling concurrent simulations. Specific simulation types, such as NVT Langevin or Frechet cell fire, utilize their own specialized [`State`](https://github.com/torchsim/torch-sim/docs/user/overview.md#L10) types that inherit from [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121). Each of these derived [`State`](https://github.com/torchsim/torch-sim/docs/user/overview.md#L10) types includes unique initialization and update functions tailored to its particular simulation context.

This architecture forms the basis for how TorchSim manages its high-level runner functions, including [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317), [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638), and [`static`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L844). These runners wrap the underlying functional approach, which involves integrators and optimizers operating on these [`State`](https://github.com/torchsim/torch-sim/docs/user/overview.md#L10) objects via [`init`](https://github.com/torchsim/torch-sim/CHANGELOG.md#L271) and [`update`](https://github.com/torchsim/torch-sim/torch_sim/properties/correlations.py#L179) functions. Further details on how these runners orchestrate simulations are available in [High-Level Simulation Runners](#atomistic-simulation-engine-core-high-level-simulation-runners) and [High-Level Simulation Runner Functions](#user-guide-to-core-concepts-high-level-simulation-runner-functions). The ability to manage batched states efficiently is also a cornerstone for TorchSim's [Autobatching Mechanisms](#atomistic-simulation-engine-core-autobatching-mechanisms), which dynamically optimizes GPU memory usage.

For ensuring reproducible simulations, [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) contains an explicit [`torch.Generator()`](https://github.com/torchsim/torch-sim/docs/user/reproducibility.md#L44) in its [`rng`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L214) attribute. Users must explicitly seed [`sim_state.rng`](https://github.com/torchsim/torch-sim/torch_sim/testing.py#L207) to ensure deterministic trajectories, as global PyTorch seeds alone are insufficient. More information on achieving reproducibility can be found in [Ensuring Reproducibility in TorchSim](#user-guide-to-core-concepts-ensuring-reproducibility-in-torchsim).
