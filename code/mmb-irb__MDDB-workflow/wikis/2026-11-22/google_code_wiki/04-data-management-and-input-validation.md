### Data Management and Input Validation
Project and MD (Molecular Dynamics) simulation data are managed and validated through a centralized system that orchestrates the entire lifecycle. This system uses an SQLite database to maintain metadata about projects and their MD replicas, tracking their status and managing their execution. The core logic for this management resides primarily within the [`/mmb-irb/mddb-workflow/mddb_workflow/core`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core) directory.

A key component for ensuring data integrity, especially in distributed computing environments, is the robust locking mechanism. The [`DatabaseLock`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L42) class, defined in [`/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py), provides a distributed filesystem-safe lock. This mechanism uses directory creation to prevent race conditions when multiple processes attempt to access or modify the shared SQLite database simultaneously, a common challenge on network file systems where traditional file locks might be unreliable. The [`Dataset`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L154) class, also in [`/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py), is responsible for interactions with this database, including adding new projects and MDs, updating their operational status (e.g., [`NEW`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L35), [`RUNNING`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L37), [`ERROR`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L38), [`DONE`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/dataset.py#L39)), and retrieving comprehensive project information. This class also incorporates logic to automatically refresh the status of running jobs by checking their process IDs or SLURM job statuses, ensuring the database accurately reflects the current state of ongoing simulations. Furthermore, it enables the generation of [`inputs.yaml`](https://github.com/mmb-irb/mddb-workflow/test/conftest.py#L90) files, critical for initializing and configuring individual simulation runs, often leveraging Jinja2 templates for flexibility.

Beyond data persistence and status tracking, the system places significant emphasis on validating and resolving complex input configurations. This is handled by the [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py) in conjunction with Pydantic schemas defined in [`/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs_schema.py). These schemas rigorously define the expected structure and data types for workflow input files (e.g., [`inputs.yaml`](https://github.com/mmb-irb/mddb-workflow/test/conftest.py#L90) or [`inputs.json`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/utils/constants.py#L67)), covering aspects from project metadata to specific simulation and analysis parameters. The [`ProjectInputs`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/core/inputs.py#L36) class manages the loading, merging, and validation of these inputs from various sources, including file-based configurations and command-line overrides. It establishes a clear precedence for input values, ensuring that defaults are applied correctly and that any inconsistencies are flagged early through an [`InputError`](https://github.com/mmb-irb/mddb-workflow/mddb_workflow/utils/auxiliar.py#L45). This system also includes specialized logic for merging and validating MD-specific configurations, supporting glob patterns for flexible file path specification, and ensuring the uniqueness and completeness of each MD setup. See [Advanced Input Configuration Resolution and Validation](#project-and-md-dataset-management-advanced-input-configuration-resolution-and-validation) for further details.
