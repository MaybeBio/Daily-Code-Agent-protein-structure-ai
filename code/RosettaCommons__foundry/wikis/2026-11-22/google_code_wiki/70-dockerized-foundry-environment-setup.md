### Dockerized Foundry Environment Setup
The Foundry project provides a reference [`Dockerfile`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L5) in [`/rosettacommons/foundry/examples/docker/Dockerfile`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile) to establish a Dockerized environment for development and execution. This Dockerfile employs a two-stage build process to optimize for both setup efficiency and runtime image size.

The initial stage, labeled [`BUILDER`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L15), is designed to prepare the complete development environment. It begins by installing system-level dependencies such as [`ca-certificates`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L21), [`git`](https://github.com/rosettacommons/foundry/README.md#L33), [`mc`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L23), and [`build-essential`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L24). Following this, it leverages [`uv`](https://github.com/rosettacommons/foundry/README.md#L26) to manage Python dependencies, creating a virtual environment, installing Foundry with all its requirements, and subsequently downloading base Foundry models into the [`/app/foundry/checkpoints`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L36) directory using the [`foundry install base-models`](https://github.com/rosettacommons/foundry/README.md#L1) command. This stage ensures that all necessary tools and model checkpoints are present before moving to the final image construction.

The second stage constructs the final, more compact runtime image. This stage copies only the essential artifacts from the [`BUILDER`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L15) stage—specifically, the configured [`/root`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L38) and [`/app`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L28) directories containing the Foundry installation and downloaded models. It also reinstalls minimal runtime system dependencies. The environment variables are set to include the Foundry virtual environment's executables in the system [`PATH`](https://github.com/rosettacommons/foundry/docs/make.bat#L19), making Foundry commands directly accessible. The working directory is set to [`/app/foundry`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L31), and the container is configured to launch with [`bash`](https://github.com/rosettacommons/foundry/README.md#L14), allowing users to interactively execute Foundry commands. This separation ensures that the final Docker image is optimized for deployment and execution, containing only what is strictly necessary for Foundry operations.
