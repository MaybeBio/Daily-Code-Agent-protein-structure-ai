## Model Evaluation Metrics and Loss Functions
The Foundry framework provides a structured approach for evaluating machine learning models through a standardized system for metrics and loss functions. This system is designed to streamline the assessment of model performance and the aggregation of various loss components during training.

The foundation of this system is the [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) abstract base class, defined in [`/rosettacommons/foundry/src/foundry/metrics/metric.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py). This class serves as a blueprint for all custom evaluation metrics. Developers extend this class and implement a [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319) method to define their specific metric calculations. The [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) class also includes mechanisms for handling input arguments, allowing metrics to specify how data from a larger input dictionary should be mapped to the arguments of their [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319) method. This includes identifying both required and optional arguments. Furthermore, metrics can be conditionally computed based on tags, enabling flexible evaluation scenarios where certain metrics are only relevant under specific conditions.

To manage and execute these individual metrics, Foundry utilizes the [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) class, also found in [`/rosettacommons/foundry/src/foundry/metrics/metric.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py). The [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) is responsible for orchestrating the instantiation, filtering, and execution of multiple [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) instances. When invoked, it processes input data, applies any tag-based filtering defined on the metrics, and then calls the [`compute_from_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L249) method for each relevant metric. The results from these computations are then aggregated into a single dictionary, with clear naming conventions (e.g., prefixing keys with the metric's name) to distinguish results from different metrics. The [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) also incorporates error handling, allowing for either the raising or suppression of exceptions that occur during metric computation.

For training, Foundry includes a [`Loss`](https://github.com/rosettacommons/foundry/src/foundry/metrics/losses.py#L8) class, located in [`/rosettacommons/foundry/src/foundry/metrics/losses.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/losses.py), which facilitates the aggregation of multiple individual loss functions into a single composite loss. This class dynamically instantiates [`torch.nn.Module`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py#L20) based loss functions from a configuration. During the forward pass, the [`Loss`](https://github.com/rosettacommons/foundry/src/foundry/metrics/losses.py#L8) class computes each registered loss function, sums their scalar values to produce a [`total_loss`](https://github.com/rosettacommons/foundry/src/foundry/metrics/losses.py#L35), and collects detailed metrics from each into a comprehensive loss dictionary. This approach provides a unified training objective while still allowing for granular insights into the contributions of individual loss components.
