### Metric Definition and Customization
The Foundry framework provides an abstract base class, [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184), found in [`/rosettacommons/foundry/src/foundry/metrics/metric.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py), which serves as the foundation for defining custom evaluation metrics. Developers extend this class to implement specific calculations by overriding the [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319) method. This method is designed to accept arbitrary keyword arguments and is expected to return a dictionary or a list of dictionaries containing the calculated metric values.

To manage how input data maps to the [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319) method's arguments, [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) offers properties like [`kwargs_to_compute_args`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L284) and [`optional_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L303). [`kwargs_to_compute_args`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L284) allows for custom mapping of incoming keyword arguments to those expected by [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319), enabling flexible data extraction from complex input structures. [`optional_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L303) specifies arguments that are not strictly required, preventing errors if they are absent from the input. Conversely, [`required_compute_args`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L237) and [`required_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L242) help identify the essential arguments needed for metric calculation.

Metrics can also be configured for conditional computation based on [`tags`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L188) provided in an [`extra_info`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L46) dictionary. This enables metrics to be activated or deactivated depending on specific conditions or properties of the data being evaluated, using [`required_tags_all`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L151), [`required_tags_any`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L155), and [`prohibited_tags`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L159). The [`compute_from_kwargs`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L249) method acts as an intermediary, processing the raw input to prepare the correct arguments for the [`compute`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L319) method, ensuring that metrics receive their necessary data in the expected format.

The [`Metric`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L184) class, along with [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) and [`MetricInputError`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L36), is made publicly available through [`/rosettacommons/foundry/src/foundry/metrics/__init__.py`](https://github.com/rosettacommons/foundry/src/foundry/metrics/__init__.py). For a broader understanding of how these metrics are orchestrated and executed, see [MetricManager for Orchestration and Execution](#model-evaluation-metrics-and-loss-functions-metricmanager-for-orchestration-and-execution).
