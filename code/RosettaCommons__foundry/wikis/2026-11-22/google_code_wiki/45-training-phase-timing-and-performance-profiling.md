### Training Phase Timing and Performance Profiling
The [`TimingCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L13) within Foundry's training framework provides performance profiling for various training phases, such as data loading iteration, the overall training step, and the optimizer step. This callback, found in [`/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py), utilizes a [`Timers`](https://github.com/rosettacommons/foundry/src/foundry/utils/torch.py#L330) object to measure durations.

The callback integrates with the training lifecycle through several hooks. It uses [`on_train_epoch_start`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L37) and [`on_after_train_loader_iter`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L41) to measure the duration of data loader iterations. The [`train_step`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L41) and [`forward_loss_backward`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L45) durations are tracked using [`on_before_train_loader_next`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L45), [`on_train_batch_start`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L49), and [`on_train_batch_end`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L53). The [`optimizer_step`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L75) duration is measured by [`on_before_optimizer_step`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L59) and [`on_after_optimizer_step`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L65).

After each optimizer step, [`TimingCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L13) accumulates these durations. It then logs and, if enabled, prints the average timings over a configurable number of steps. This aggregation provides a stable overview of performance characteristics without overwhelming the logs with per-step details. All logging and timing operations are executed only on the global rank zero process in distributed environments, leveraging the [`@rank_zero_only`](https://github.com/rosettacommons/foundry/src/foundry/utils/logging.py#L126) decorator to prevent redundant outputs. For more details on the general callback system, refer to [Callback System for Training Workflow Automation](#foundry-core-library-and-ml-workflows-callback-system-for-training-workflow-automation) and [Core Callback Design and Extension](#machine-learning-callbacks-core-callback-design-and-extension).
