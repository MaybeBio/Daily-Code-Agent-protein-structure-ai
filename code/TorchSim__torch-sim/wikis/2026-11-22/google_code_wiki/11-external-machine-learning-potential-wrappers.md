### External Machine Learning Potential Wrappers
[`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) provides comprehensive integration with various external machine learning interatomic potentials (MLIPs), allowing these advanced models to be used seamlessly within its simulation framework. This is achieved through dedicated wrapper classes that conform to the [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) defined in [`/torchsim/torch-sim/torch_sim/models/interface.py`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py). This ensures that MLIPs, regardless of their original implementation, present a consistent API for energy, force, and stress calculations.

Each MLIP integration typically follows a similar pattern. A wrapper class, such as [`MaceModel`](https://github.com/torchsim/torch-sim/torch_sim/models/mace.py#L22) for MACE (in [`/torchsim/torch-sim/torch_sim/models/mace.py`](https://github.com/torchsim/torch-sim/torch_sim/models/mace.py)), [`NequIPFrameworkModel`](https://github.com/torchsim/torch-sim/torch_sim/models/nequip_framework.py#L19) for NequIP and Allegro (in [`/torchsim/torch-sim/torch_sim/models/nequip_framework.py`](https://github.com/torchsim/torch-sim/torch_sim/models/nequip_framework.py)), [`NequixModel`](https://github.com/torchsim/torch-sim/torch_sim/models/nequix.py#L20) for Nequix (in [`/torchsim/torch-sim/torch_sim/models/nequix.py`](https://github.com/torchsim/torch-sim/torch_sim/models/nequix.py)), [`OrbModel`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L25) for ORB (in [`/torchsim/torch-sim/torch_sim/models/orb.py`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py)), [`SevenNetModel`](https://github.com/torchsim/torch-sim/torch_sim/models/sevennet.py#L23) for SevenNet (in [`/torchsim/torch-sim/torch_sim/models/sevennet.py`](https://github.com/torchsim/torch-sim/torch_sim/models/sevennet.py)), [`MatterSimModel`](https://github.com/torchsim/torch-sim/torch_sim/models/mattersim.py#L24) for MatterSim (in [`/torchsim/torch-sim/torch_sim/models/mattersim.py`](https://github.com/torchsim/torch-sim/torch_sim/models/mattersim.py)), or [`MetatomicModel`](https://github.com/torchsim/torch-sim/torch_sim/models/metatomic.py#L20) for metatomic-based models (in [`/torchsim/torch-sim/torch_sim/models/metatomic.py`](https://github.com/torchsim/torch-sim/torch_sim/models/metatomic.py)), is defined. These wrappers handle the necessary data transformations between the [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) object (the universal state representation in [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3)) and the input formats expected by the external MLIPs. They also manage the extraction and reformatting of outputs (energies, forces, stresses) from the MLIPs back into [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3)'s standardized dictionary format.

A key design consideration for these integrations is the robust fallback mechanism. Since external MLIPs are often optional dependencies, [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) implements a "safe import" pattern. If an external library (e.g., [`mace`](https://github.com/torchsim/torch-sim/pyproject.toml#L53), [`nequip`](https://github.com/torchsim/torch-sim/pyproject.toml#L59), [`orb-models`](https://github.com/torchsim/torch-sim/CHANGELOG.md#L67)) is not installed, the corresponding wrapper class becomes a dummy placeholder. This dummy class inherits from [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) but will raise an [`ImportError`](https://github.com/torchsim/torch-sim/torch_sim/io.py#L60) immediately upon instantiation, clearly indicating the missing dependency. This prevents hard crashes at import time and provides clear, actionable feedback to the user when they attempt to use a feature that requires an uninstalled external package. For instance, the [`warnings`](https://github.com/torchsim/torch-sim/pyproject.toml#L145) module is used to notify developers about failed imports, such as for [`FairChemModel`](https://github.com/torchsim/torch-sim/torch_sim/models/fairchem.py#L23) in [`/torchsim/torch-sim/torch_sim/models/fairchem.py`](https://github.com/torchsim/torch-sim/torch_sim/models/fairchem.py).

In addition to basic wrapping, some MLIP integrations include specific model-dependent utilities. For example, the [`OrbModel`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L25) in [`/torchsim/torch-sim/torch_sim/models/orb.py`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py) includes a [`_normalize_charge_spin`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L29) static method to ensure that the [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) provides required [`charge`](https://github.com/torchsim/torch-sim/torch_sim/units.py#L105) and [`spin`](https://github.com/torchsim/torch-sim/torch_sim/typing.py#L35) attributes, defaulting them to zero if missing. It also has a [`_get_results`](https://github.com/torchsim/torch-sim/torch_sim/models/orb.py#L42) method to parse raw ORB model outputs, including property renaming and reshaping stress tensors from Voigt notation if necessary. This illustrates how wrappers adapt [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) properties and model outputs to ensure full compatibility.

By conforming to the [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71), these external MLIP wrappers can be seamlessly integrated into [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3)'s high-level simulation runners, such as [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317) and [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638), and leverage features like autobatching and trajectory reporting. More details on the [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) and model composition can be found in [Model Interface and Composition](#model-implementations-and-integration-model-interface-and-composition).
