## Machine Learning Callbacks
Foundry employs a standardized callback system to integrate various functionalities into its machine learning training workflows. This system allows for the dynamic injection of custom logic at different stages of the training and validation processes, promoting modularity and extensibility. The core of this system is the abstract [`BaseCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L9) class, defined in [`/rosettacommons/foundry/src/foundry/callbacks/callback.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py), which provides a comprehensive set of hook methods that concrete implementations can override. These hooks allow interaction with the [`trainer`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L287) object, providing access to its state and Fabric utilities.

Key functionalities implemented through this callback system include:

*   **Model Health Tracking**: The [`ActivationsGradientsWeightsTracker`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/health_logging.py#L48) callback in [`/rosettacommons/foundry/src/foundry/callbacks/health_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/health_logging.py) monitors and logs statistics of a model's gradients, weights, and activations. It registers hooks to capture activations and iterates over model parameters to collect summary statistics and histogram data. This tracking helps in diagnosing training issues and understanding model behavior over time.
*   **Validation Metrics Aggregation**: For distributed training, the [`StoreValidationMetricsInDFCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py#L16) in [`/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py) collects and aggregates per-batch validation metrics across different processing ranks. It ensures that metrics generated on each rank are saved and then reliably combined by the global rank zero, handling potential duplicates to produce a unified view of validation performance.
*   **Performance Profiling**: The [`TimingCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py#L13) in [`/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/timing_logging.py) provides detailed profiling of various training phases, such as data loading, forward and backward passes, and optimizer steps. It uses an internal [`Timers`](https://github.com/rosettacommons/foundry/src/foundry/utils/torch.py#L330) object to measure durations, logging and optionally printing average timings at specified intervals to analyze and optimize training efficiency.
*   **Comprehensive Training Progress Logging**: Found in [`/rosettacommons/foundry/src/foundry/callbacks/train_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/train_logging.py), various callbacks are dedicated to logging training progress. These include callbacks for logging model parameter counts, debugging [`example_id`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L95)s per batch, monitoring dataset sampling ratios, tracking the optimizer's learning rate, and providing detailed breakdowns of training losses. These callbacks leverage rich console output for enhanced readability and structured reporting of key training metrics.

This callback architecture, as described further in [Training Harness with PyTorch Lightning Fabric](#foundry-core-library-and-ml-workflows-training-harness-with-pytorch-lightning-fabric), allows developers to inject custom logic for monitoring, logging, and dynamic adjustment of training parameters without altering the core training loop.
