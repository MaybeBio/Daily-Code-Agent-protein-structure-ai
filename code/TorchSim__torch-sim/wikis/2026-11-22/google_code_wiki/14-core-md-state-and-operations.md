### Core MD State and Operations
The central component for managing molecular dynamics (MD) simulations is the [`MDState`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L32) dataclass, defined in [`/torchsim/torch-sim/torch_sim/integrators/md.py`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py). This class extends the general [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) dataclass (see [Core Simulation State Management](#atomistic-simulation-engine-core-core-simulation-state-management)) and serves as a container for all dynamic variables necessary to describe an atomistic system's state at any given time during an MD simulation. Key attributes include atomic [`momenta`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L62), [`energy`](https://github.com/torchsim/torch-sim/torch_sim/units.py#L104), and [`forces`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L904), alongside inherited properties such as [`positions`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L177), [`masses`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L178), [`cell`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L179), and periodic boundary conditions ([`pbc`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L180)). [`MDState`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L32) also provides computed properties like [`velocities`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L74) and methods for calculating system [`temperature`](https://github.com/torchsim/torch-sim/torch_sim/units.py#L112) and [`kT`](https://github.com/torchsim/torch-sim/examples/scripts/7_others.py#L151).

Building upon the [`MDState`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L32), several foundational operations underpin all MD integrators. The [`initialize_momenta`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L113) function in [`/torchsim/torch-sim/torch_sim/integrators/md.py`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py) is responsible for setting the initial velocities of particles by sampling from a Maxwell-Boltzmann distribution at a specified temperature, ensuring the removal of center-of-mass motion to prevent system drift. This thermalization step is crucial for starting simulations in a physically meaningful state.

The advancement of the simulation through time relies on core stepping functions:
*   [`momentum_step`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L169): This function, located in [`/torchsim/torch-sim/torch_sim/integrators/md.py`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py), updates particle momenta based on the forces currently acting on them and the simulation timestep. It also ensures that any defined constraints on momenta are applied.
*   [`position_step`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L190): Also in [`/torchsim/torch-sim/torch_sim/integrators/md.py`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py), this function updates particle positions based on their current velocities and the timestep, incorporating any positional constraints.

These basic steps are combined in the [`velocity_verlet_step`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L211) function, which implements one full step of the Velocity Verlet integration algorithm. This algorithm is widely used in MD for its accuracy, symplecticity, and time-reversibility, which are important for conserving total energy in microcanonical (NVE) simulations. A single Velocity Verlet step involves a half momentum update, a full position update, a recalculation of forces and energies by the [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71), and a final half momentum update. This sequence ensures that positions, velocities, and forces are consistently advanced. All integrators, including those for NVE, NVT, and NPT ensembles (discussed further in [Simulation Integrators](#simulation-integrators)), build upon these fundamental [`MDState`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L32) management and stepping functions.

The Nose-Hoover chain thermostatting mechanism, used for constant temperature simulations, is also defined within [`/torchsim/torch-sim/torch_sim/integrators/md.py`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py). This includes the [`NoseHooverChain`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L249) dataclass for storing thermostat state variables and [`NoseHooverChainFns`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L276) for encapsulating associated operations. The [`construct_nose_hoover_chain`](https://github.com/torchsim/torch-sim/torch_sim/integrators/md.py#L338) factory function configures the thermostat's behavior based on parameters like relaxation time and chain length, preparing it for integration into NVT and NPT schemes.
