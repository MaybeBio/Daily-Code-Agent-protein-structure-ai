### MPNN Data Preparation and Training Pipelines
The data preparation and transformation pipelines for MPNN models are designed to convert raw structural data into a format suitable for model input, supporting both training and inference. The [`build_mpnn_transform_pipeline`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py#L61) function, located in [`/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py), constructs a [`Compose`](https://github.com/rosettacommons/foundry/src/foundry/utils/rigid.py#L626) object that orchestrates a series of transformations. This pipeline allows for conditional processing, applying specific transformations based on whether the data is for training or inference, and whether the model type is [`protein_mpnn`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L154) or [`ligand_mpnn`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L155).

The pipeline begins with data filtering and preprocessing, including the removal of hydrogen atoms and the handling of undesired residue tokens. It then proceeds with atomization and residue indexing, which involves adding within-chain residue indices, handling covalent modifications, and flagging non-polymeric components for atomization. Occupancy-based masking is used to filter out residues with unresolved backbone atoms. Crucially, the [`FeaturizeUserSettings`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py#L21) class in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py) prepares user-defined parameters, such as [`structure_noise`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1995) for data augmentation during training and [`decode_type`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1998) for inference, integrating them into the model's features. Interface computation for ligand models is managed by [`ComputePolymerLigandInterface`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py#L17) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py), which identifies and marks polymer atoms interacting with ligands, and [`FeaturizePolymerLigandInterfaceMask`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py#L16) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py), which generates a residue-level mask for these interactions.

The training infrastructure, orchestrated by the script in [`/rosettacommons/foundry/models/mpnn/src/mpnn/train.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py), sets up the environment for training MPNN models. This includes defining a NoamOpt-style learning rate scheduler to dynamically adjust the learning rate during training. Datasets are prepared using [`StructuralDatasetWrapper`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L9), which integrates with [`GenericDFParser`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L10) for structural data and applies the transformation pipelines. For efficient training, particularly with variable-length protein sequences, [`PaddedTokenBudgetBatchSampler`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/samplers/samplers.py#L9) from [`/rosettacommons/foundry/models/mpnn/src/mpnn/samplers/samplers.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/samplers/samplers.py) creates batches based on a token budget, optimizing GPU memory usage. A [`TokenBudgetAwareFeatureCollator`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/collate/feature_collator.py#L187) from [`/rosettacommons/foundry/models/mpnn/src/mpnn/collate/feature_collator.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/collate/feature_collator.py) combines samples into batches while respecting token budget constraints.

The [`MPNNTrainer`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/trainers/mpnn.py#L21) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/trainers/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/trainers/mpnn.py) manages the overall training and validation loops. It handles model construction, loss calculation, and metric computation. The primary loss function used is [`LabelSmoothedNLLLoss`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/loss/nll_loss.py#L7) from [`/rosettacommons/foundry/models/mpnn/src/mpnn/loss/nll_loss.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/loss/nll_loss.py), a negative log-likelihood loss with label smoothing to improve generalization. The training setup also includes checkpointing functionality to save and load model states, facilitating continued training and reproducibility.
