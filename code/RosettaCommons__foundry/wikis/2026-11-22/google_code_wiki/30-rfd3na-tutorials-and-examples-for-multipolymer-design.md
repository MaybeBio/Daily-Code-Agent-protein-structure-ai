### RFD3NA Tutorials and Examples for Multipolymer Design
The [`/rosettacommons/foundry/models/rfd3na/docs/tutorials`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/tutorials) directory provides practical guides for utilizing RFdiffusion3NA (RFD3NA) to design diverse biomolecular systems, including enzymes, nucleic acid binders, and protein-protein interfaces. These tutorials demonstrate how to configure and execute design tasks, emphasizing the use of JSON or YAML configuration files to define design parameters and constraints.

For **enzyme design**, the [`enzyme_design_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3/docs/index.rst#L28) ([`/rosettacommons/foundry/models/rfd3na/docs/tutorials/enzyme_design_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/tutorials/enzyme_design_tutorial.md)) focuses on designing around specific catalytic residues and controlling the protein's interaction with a ligand. Key configuration parameters include [`input`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L132) (PDB file), [`ligand`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L142) identification, [`unindex`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L135) to allow sequence redesign in specified regions, and [`length`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L141) to define the size of the designed protein. [`select_fixed_atoms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L152) is used to constrain atoms to maintain their positions, while [`select_buried`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L170) and [`select_exposed`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L172) apply RASA (Relative Accessible Surface Area) conditioning to guide ligand interaction. The [`select_unfixed_sequence`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L160) parameter enables sequence optimization for fixed backbone regions, illustrating a design approach that decouples sequence from structure.

The [`na_binder_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3/docs/index.rst#L29) ([`/rosettacommons/foundry/models/rfd3na/docs/tutorials/na_binder_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/tutorials/na_binder_tutorial.md)) outlines the process for **nucleic acid binder design**, specifically focusing on DNA-protein complexes. This tutorial introduces the [`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) parameter for defining both fixed and *de novo* designed segments, including nucleic acid (DNA or RNA) and protein chains. [`unindex`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L135) allows for "unindexed motifs" whose positions are determined during diffusion, and their placement is tracked using [`diffused_index_map`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L404) in the output. [`select_fixed_atoms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L152) (e.g., [`BKBN`](https://github.com/rosettacommons/foundry/models/rfd3na/README.md#L90) for backbone only) can be used to stabilize parts of the input structure, while [`is_non_loopy`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L191) encourages designs with minimal loops. Hydrogen bond conditioning can be incorporated using [`select_hbond_acceptor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L174) and [`select_hbond_donor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L175) with an external tool like HBPLUS.

For **protein-protein interface (PPI) design**, the [`ppi_design_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3/docs/index.rst#L27) ([`/rosettacommons/foundry/models/rfd3na/docs/tutorials/ppi_design_tutorial.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/tutorials/ppi_design_tutorial.md)) illustrates how to configure RFD3NA to generate protein binders. This tutorial leverages [`select_hotspots`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L176) to define specific residues on the target protein that the designed binder should interact with. The [`infer_ori_strategy: hotspots`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/utils/inference.py#L399) setting places the origin token for the designed protein relative to these hotspots, biasing the diffusion process towards desired interaction sites. Similar to nucleic acid binder design, [`is_non_loopy: true`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L70) helps produce less looped structures. The tutorial also highlights a broader design workflow where RFD3NA is followed by other tools for filtering, sequence redesign (e.g., with ProteinMPNN as discussed in [Protein and Ligand Inverse Folding (MPNN)](#protein-and-ligand-inverse-folding-mpnn)), and structure validation (e.g., with RoseTTAFold3, covered in [RoseTTAFold3 (RF3) for Structure Prediction](#rosettafold3-rf3-for-structure-prediction)).

All tutorials use the [`rfd3 design`](https://github.com/rosettacommons/foundry/README.md#L1) command-line tool, providing parameters such as [`out_dir`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L103) for output location, [`inputs`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L102) pointing to the configuration file, and [`ckpt_path`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L45) for specifying model checkpoints. Output analysis involves examining [`.cif.gz`](https://github.com/rosettacommons/foundry/models/rf3/README.md#L620) files for structural visualization and [`.json`](https://github.com/rosettacommons/foundry/models/rfd3/README.md#L67) files for detailed metadata, including [`diffused_index_map`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L404) and [`diffused_com`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/metrics/design_metrics.py#L155) (new origin token location). The system's JSON-based configuration allows for declarative specification of complex design scenarios, from simple protein designs to intricate hybrid designs with specific secondary structure, base-pairing, and ligand-interaction constraints, as further elaborated in [`atom23_design.md`](https://github.com/rosettacommons/foundry/models/rfd3na/README.md#L71) ([`/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/examples/atom23_design.md)) and the [`input.md`](https://github.com/rosettacommons/foundry/models/rfd3/README.md#L14) documentation ([`/rosettacommons/foundry/models/rfd3na/docs/input.md`](https://github.com/rosettacommons/foundry/models/rfd3na/docs/input.md)). These examples collectively demonstrate RFD3NA's flexibility in addressing diverse biomolecular design challenges.
