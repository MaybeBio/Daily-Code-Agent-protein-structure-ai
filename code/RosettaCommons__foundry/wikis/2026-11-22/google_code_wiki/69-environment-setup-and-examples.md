## Environment Setup and Examples
Foundry provides clear guidance for setting up development and execution environments, primarily through a reference [`Dockerfile`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L5) located in [`/rosettacommons/foundry/examples/docker/Dockerfile`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile). This Dockerfile streamlines the process of creating a custom Foundry image, simplifying environment configuration, dependency management, and base model downloads.

The Dockerfile employs a two-stage build process. The initial [`BUILDER`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L15) stage is responsible for setting up the comprehensive development environment. This includes installing system dependencies such as [`git`](https://github.com/rosettacommons/foundry/README.md#L33) and [`build-essential`](https://github.com/rosettacommons/foundry/examples/docker/Dockerfile#L24), creating a Python virtual environment, and installing Foundry with all its dependencies. Crucially, it also handles the download of base Foundry models into a designated [`checkpoints`](https://github.com/rosettacommons/foundry/.env#L62) directory. Following this, the final image stage copies the prepared environment, ensuring that the runtime image is optimized for execution while still including all necessary components and pre-downloaded models. The [`PATH`](https://github.com/rosettacommons/foundry/docs/make.bat#L19) environment variable is configured to allow direct execution of Foundry commands within the container.
