### SLURM-based Uniclust30 Alignment Generation
The generation of Uniclust30 all-against-all alignments on SLURM clusters is managed by the [`/aqlaboratory/openfold/scripts/slurm_scripts/run_uniclust30_search.sh`](https://github.com/aqlaboratory/openfold/scripts/slurm_scripts/run_uniclust30_search.sh) script. This script is designed to efficiently distribute and execute the demanding [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30) search operations across multiple nodes in a high-performance computing environment.

The process begins by transferring the Uniclust30 database files to a local SSD on each compute node. This step is performed to minimize I/O bottlenecks and accelerate [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30) execution. To prevent redundant computations, the script identifies and filters out protein entries that have already been processed, ensuring that [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30) only runs on new or incomplete alignment tasks.

The filtered input data is then split into node-specific chunks, allowing each SLURM node to process a distinct subset of the Uniclust30 database. This division of labor enables parallel execution of [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30). A semaphore mechanism is employed to control the number of concurrent [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30) instances on each node, optimizing resource utilization.

As [`hhblits`](https://github.com/aqlaboratory/openfold/openfold/data/tools/hhblits.py#L30) generates alignments, the script periodically checks the size of the temporary scratch directory. To manage storage effectively, results are compressed into [`.zip`](https://github.com/aqlaboratory/openfold/notebooks/OpenFold.ipynb#L807) archives in a designated output directory, and the temporary scratch directories are cleaned up. This systematic approach ensures efficient data management and scalability for large-scale alignment generation. For broader context on managing OpenFold's operational scripts, see [OpenFold Management Scripts](#openfold-management-scripts).
