### RFD3 Training Pipeline and Conditioning Strategies
The RFD3 training pipeline is primarily managed by the [`train`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/train.py#L26) function in [`/rosettacommons/foundry/models/rfd3/src/rfd3/train.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/train.py), which leverages [`hydra`](https://github.com/rosettacommons/foundry/pyproject.toml#L27) for configuration and [`lightning.fabric`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L84) for distributed training. This setup allows for flexible experimentation and scalable training across multiple hardware configurations. The pipeline initializes a [`RankedLogger`](https://github.com/rosettacommons/foundry/src/foundry/utils/ddp.py#L58) for managing distributed logging and uses [`instantiate_loggers`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py#L47) and [`instantiate_callbacks`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py#L19) to dynamically set up monitoring and workflow automation.

Central to RFD3's training is the [`AADesignTrainer`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L33) located in [`/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py). This trainer orchestrates the model's forward and backward passes, loss calculations, and metric computations specific to protein design tasks. It extends the abstract [`FabricTrainer`](https://github.com/rosettacommons/foundry/src/foundry/trainers/fabric.py#L56) (see [Training Harness with PyTorch Lightning Fabric](#foundry-core-library-and-ml-workflows-training-harness-with-pytorch-lightning-fabric)) to handle the lifecycle of training and validation loops, ensuring consistent behavior in distributed environments.

A key aspect of RFD3's training is its sophisticated conditioning strategy, which creates diverse design problems during training. This involves fixing specific "motif tokens," atoms, sequences, or coordinates within a structure, guided by [`training_conditions`](https://github.com/rosettacommons/foundry/models/rfd3/README.md#L171) specified in the configuration files under [`global_transform_args`](https://github.com/rosettacommons/foundry/models/rfd3/README.md#L171). These conditions, processed by data transforms in [`/rosettacommons/foundry/models/rfd3/src/rfd3/transforms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/transforms), enable the model to learn to generate novel structures under various constraints. For instance, [`_assemble_network_inputs`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/trainers/rf3.py#L111) within [`AADesignTrainer`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/rfd3.py#L33) is responsible for preparing and validating these conditioned inputs for the model, ensuring data integrity with checks for NaNs and consistent tensor shapes. The training process also incorporates a recycling schedule, managed by [`get_recycle_schedule`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/utils/recycling.py#L7) from [`/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/recycling.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/trainer/recycling.py), which defines the number of recycling steps per batch for distributed training, enhancing model performance and stability.
