### High-Level Simulation Runners
The [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) package provides high-level runner functions that abstract the complexities of orchestrating molecular dynamics simulations, geometry optimizations, and single-point calculations. These runners serve as primary entry points for executing atomistic simulations, managing state, and reporting results. They are designed to leverage automatic batching for performance and integrate trajectory reporting for data persistence. These functions are located in [`/torchsim/torch-sim/torch_sim/runners.py`](https://github.com/torchsim/torch-sim/torch_sim/runners.py) and exposed at the top level of the package via [`/torchsim/torch-sim/torch_sim/__init__.py`](https://github.com/torchsim/torch-sim/torch_sim/__init__.py).

The three main runner functions are:

*   **[`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317)**: This function is responsible for performing molecular dynamics (MD) simulations. It takes an initial simulation state, a chosen integrator (e.g., NVE, NVT, NPT), and a model (for energy/force calculations) as input. It then advances the simulation for a specified number of steps, applying the selected integrator's rules to evolve the system's positions and momenta. The [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317) function uses a [`TrajectoryReporter`](https://github.com/torchsim/torch-sim/torch_sim/trajectory.py#L68) to log simulation data at regular intervals, enabling post-simulation analysis. For efficiency, it employs a [`BinningAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L475) to group systems into fixed batches, ensuring optimal utilization of GPU resources during the MD run. More details on the available integrators can be found in [Simulation Integrators](#simulation-integrators).

*   **[`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638)**: This function orchestrates geometry optimizations, seeking to find stable atomic configurations by minimizing the system's energy. It requires an initial simulation state, an optimizer (such as Gradient Descent, BFGS, L-BFGS, or FIRE), and a model. The optimization process continues until a predefined convergence criterion is met, typically when forces or energy changes fall below a certain threshold. A key feature of [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638) is its use of an [`InFlightAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L768), which dynamically manages batches of systems. This allows the runner to efficiently process multiple optimization tasks simultaneously, removing systems from the batch as they converge and potentially adding new ones, thereby maximizing throughput. The module also provides utility functions, such as [`generate_energy_convergence_fn`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L612) and [`generate_force_convergence_fn`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L572), to help define these convergence criteria. For a deeper understanding of the optimizers, refer to [Geometry Optimization Algorithms](#geometry-optimization-algorithms).

*   **[`static`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L844)**: This function performs single-point calculations, which involve evaluating the energy, forces, and stress for a given atomic configuration without evolving its state over time. It takes a [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) and a model as input and returns these computed properties. The [`static`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L844) function is often used as a preliminary step in more complex workflows or for analyzing specific snapshots from a simulation. It leverages the underlying model's capabilities to compute these properties efficiently, including support for batch processing.

All three runners are designed to interact with a [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) [Model Interface and Composition](#model-implementations-and-integration-model-interface-and-composition) for energy, force, and stress calculations, making them highly flexible with respect to the interatomic potential used. They manage [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) objects [Core Simulation State Management](#atomistic-simulation-engine-core-core-simulation-state-management) that encapsulate atomistic system properties, handling transformations and updates across simulation steps. The autobatching mechanisms, specifically [`BinningAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L475) and [`InFlightAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L768) [Autobatching Mechanisms](#atomistic-simulation-engine-core-autobatching-mechanisms), play a crucial role in optimizing performance by intelligently managing GPU memory and processing varying system sizes.
