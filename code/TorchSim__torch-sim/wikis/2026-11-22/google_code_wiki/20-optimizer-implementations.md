### Optimizer Implementations
The [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) repository provides a suite of geometry optimization algorithms for the relaxation of atomic structures, designed to operate efficiently on batched systems. These optimizers can handle both position-only minimization and extended optimizations that include cell parameters. The overall design leverages a flexible filter-based mechanism for managing cell constraints and parameterizations.

The available optimization algorithms include:
*   **Gradient Descent:** This is a fundamental optimization algorithm that updates atomic positions based on computed forces and a specified learning rate. It supports cell optimization by updating cell parameters according to a [`cell_filter`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/cell_filters.py#L431) and a cell-specific learning rate, as detailed in [`/torchsim/torch-sim/torch_sim/optimizers/gradient_descent.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/gradient_descent.py). Its initialization involves setting up the initial state with forces and energies, while each step updates positions and re-evaluates the model for new forces.
*   **FIRE (Fast Inertial Relaxation Engine):** The FIRE algorithm is implemented to accelerate geometry optimizations. It dynamically adjusts the timestep and a mixing parameter based on the system's "power" (the dot product of forces and velocities), allowing for rapid convergence to energy minima. Two flavors are provided: a Velocity-Verlet based approach and an ASE-mimicking implementation, both managed by [`fire_init`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/fire.py#L22) and [`fire_step`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/fire.py#L117) functions in [`/torchsim/torch-sim/torch_sim/optimizers/fire.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/fire.py). State management for FIRE involves tracking velocities, timestep, and the mixing parameter [`alpha`](https://github.com/torchsim/torch-sim/torch_sim/integrators/npt.py#L102).
*   **BFGS (Broyden-Fletcher-Goldfarb-Shanno):** The BFGS optimizer, found in [`/torchsim/torch-sim/torch_sim/optimizers/bfgs.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/bfgs.py), is a quasi-Newton method that approximates the Hessian matrix to determine search directions. It is suitable for systems with a moderate number of atoms where the memory cost of storing a full Hessian per system is manageable. The [`bfgs_init`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/bfgs.py#L87) function initializes the Hessian and other state variables, while [`bfgs_step`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/bfgs.py#L216) updates the Hessian approximation, computes the step using eigendecomposition to ensure a descent direction, and applies the update to positions and optionally cell parameters.
*   **L-BFGS (Limited-memory BFGS):** As an alternative to BFGS, L-BFGS (implemented in [`/torchsim/torch-sim/torch_sim/optimizers/lbfgs.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/lbfgs.py)) offers a more memory-efficient approach by maintaining only a limited history of position and gradient differences instead of a full Hessian. This history is used in a "two-loop recursion" to approximate the inverse Hessian and compute the search direction. [`lbfgs_init`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/lbfgs.py#L114) sets up the initial state and history tensors, and [`lbfgs_step`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/lbfgs.py#L262) executes the two-loop recursion, updates positions and cell parameters, and refreshes the history.

All optimizers utilize dedicated state management classes, such as [`OptimState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/state.py#L12), [`FireState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/state.py#L39), [`BFGSState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/state.py#L55), and [`LBFGSState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/state.py#L102), which extend the core [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) dataclass to include algorithm-specific parameters like forces, energies, velocities, and historical data. When cell optimization is active, specialized states like [`CellOptimState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/cell_filters.py#L427) or [`CellFireState`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/cell_filters.py#L458) are employed, which incorporate cell-specific attributes and interact with the [Cell Optimization and Filter-Based Design](#geometry-optimization-algorithms-cell-optimization-and-filter-based-design) mechanisms. These state objects are designed to handle batched systems with varying atom counts efficiently through padding and careful attribute management, as described in [`/torchsim/torch-sim/torch_sim/optimizers/state.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/state.py).

The specific optimizer used can be dynamically selected via the [`OPTIM_REGISTRY`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/__init__.py#L47), which maps an [`Optimizer`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/__init__.py#L38) enumeration to its corresponding initialization and step functions, as defined in [`/torchsim/torch-sim/torch_sim/optimizers/__init__.py`](https://github.com/torchsim/torch-sim/torch_sim/optimizers/__init__.py).
