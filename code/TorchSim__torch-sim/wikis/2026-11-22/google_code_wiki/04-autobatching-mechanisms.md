### Autobatching Mechanisms
Autobatching in TorchSim optimizes GPU memory usage and computational efficiency by dynamically managing batches of atomistic simulation states. This is particularly important because simulation states, characterized by properties like the number of atoms, can vary significantly in their memory footprint. The framework provides mechanisms to estimate memory requirements and adjust batch sizes accordingly, preventing out-of-memory errors and maximizing GPU utilization.

The core of TorchSim's autobatching capabilities is found in the [`autobatching`](https://github.com/torchsim/torch-sim/docs/user/overview.md#L16) module ([`/torchsim/torch-sim/torch_sim/autobatching.py`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py)). It includes functionalities for estimating the GPU memory consumed by a model's forward pass, which is then used to determine the maximum number of simulation states that can be processed concurrently. This estimation leverages memory scaling metrics such as the number of atoms ([`n_atoms`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L428)), the product of atom count and density ([`n_atoms_x_density`](https://github.com/torchsim/torch-sim/torch_sim/typing.py#L79)), or the actual number of neighbor list edges ([`n_edges`](https://github.com/torchsim/torch-sim/CHANGELOG.md#L89)), offering flexibility based on the model's computational dependencies.

Two primary autobatching strategies are implemented to suit different simulation workflows:

*   **[`BinningAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L475)**: This strategy pre-allocates simulation states into fixed batches. It is designed for scenarios where all input states need to undergo the same number of simulation steps, such as in molecular dynamics runs where the batch composition remains constant over time. The [`to_constant_volume_bins`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L46) function ([`/torchsim/torch-sim/torch_sim/autobatching.py`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py)) groups states by their estimated memory usage into bins, optimizing packing efficiency similar to bin packing algorithms. Once batched, the [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317) runner function leverages this for efficient, static batch processing. See [High-Level Simulation Runners](#atomistic-simulation-engine-core-high-level-simulation-runners) for more details.

*   **[`InFlightAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L768)**: This mechanism dynamically manages batches, particularly useful for iterative processes like geometry optimization where states converge at different rates. It can "hot-swap" converged states out of a batch and replace them with new, unconverged states. This dynamic approach ensures that GPU resources are continuously utilized by active simulations. The [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638) runner function uses [`InFlightAutoBatcher`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L768) to efficiently manage systems during geometry optimizations, dynamically removing converged systems and adding new ones until all systems have reached their convergence criteria. This process also prevents memory leaks by detaching the computational graph of completed states. See [High-Level Simulation Runners](#atomistic-simulation-engine-core-high-level-simulation-runners) for more details.

Both batchers operate on [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) objects, which are designed to support efficient concatenation and splitting, enabling seamless manipulation of batched data. The [`determine_max_batch_size`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L195) function ([`/torchsim/torch-sim/torch_sim/autobatching.py`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py)) is crucial for both strategies, finding the largest possible batch size that fits in GPU memory using an iterative search, while also implementing memory safety measures like releasing the CUDA caching allocator to avoid memory fragmentation. This adaptive approach ensures that TorchSim simulations are both memory-efficient and performant across a wide range of system sizes and computational models.
