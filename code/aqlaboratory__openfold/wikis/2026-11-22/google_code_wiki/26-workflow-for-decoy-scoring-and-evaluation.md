### Workflow for Decoy Scoring and Evaluation
The evaluation of protein structure prediction models in OpenFold involves a workflow that scores protein decoys against native structures. This process is managed by the code in [`/aqlaboratory/openfold/experiments`](https://github.com/aqlaboratory/openfold/experiments). This framework orchestrates the generation of OpenFold predictions, using either native structures or alternative decoy structures as templates, and then quantifies the accuracy of these predictions.

The evaluation process begins with processing a list of target proteins and their corresponding decoys. For each decoy, a [`Decoy`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L326) namedtuple stores relevant metadata such as the target name, decoy identifier, and file paths. This metadata is crucial for organizing and managing the various inputs and outputs throughout the evaluation.

When preparing templates for OpenFold, the [`score_decoy`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L217) function converts an input protein decoy, represented as a [`protein`](https://github.com/aqlaboratory/openfold/openfold/np/protein.py#L45) object, into the specific features required by the OpenFold model. This conversion includes generating template atom positions, masks, and amino acid types. The process also offers options for feature engineering, such as masking sidechain atoms or adding C-beta atoms for glycines, which can influence how the model incorporates template information.

Once the template features are prepared, an OpenFold model, configured through [`make_model_runner`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L106), generates a protein structure prediction. The model can be run with various settings, such as the number of recycles, which determines how many times the model refines its prediction. After the prediction, [`parse_results`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L185) extracts key information from OpenFold's output, including the predicted unrelaxed protein structure, per-residue predicted lDDT (pLDDT) scores, and a predicted TM-score.

The final step involves comparing the OpenFold prediction against the native structure and the original decoy. Structural similarity metrics such as Root Mean Square Deviation (RMSD) and TM-score are calculated. The [`jnp_rmsd`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L89) function computes RMSD, while [`compute_tmscore`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L303) executes an external TM-score program to obtain TM-score values. The [`write_results`](https://github.com/aqlaboratory/openfold/experiments/test_templates_openfold.py#L332) function then aggregates these metrics, saves the predicted PDB files, and appends all results to CSV files, ensuring persistence and traceability of the evaluation outcomes. For a broader understanding of how structural similarity metrics and external tools are integrated into this process, refer to [Structural Similarity Metrics and External Tool Integration](#experimentation-and-model-evaluation-structural-similarity-metrics-and-external-tool-integration). The overall framework also supports resuming interrupted runs by tracking finished decoys and targets, which contributes to the robustness of the evaluation pipeline.
