### MPNN Data Preparation and Transformation Pipelines
The data preparation and transformation pipelines for MPNN models convert raw structural data into a feature set suitable for model input, encompassing cleaning, atomization, featurization of user settings, and calculations for polymer-ligand interfaces. These pipelines are primarily defined and configured within the [`/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines) directory, where the [`build_mpnn_transform_pipeline`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py#L61) function constructs a [`Compose`](https://github.com/rosettacommons/foundry/src/foundry/utils/rigid.py#L626) object. This object orchestrates a series of transformations for both training and inference scenarios, adapting based on configuration parameters such as [`model_type`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L26) (protein or ligand MPNN), [`occupancy_threshold`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py#L139), and [`is_inference`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/testing/debug.py#L38).

The process begins with structural cleaning, which includes removing hydrogen atoms and handling undesired residues or non-clashing chains during training. The system then performs atomization and residue processing, adding within-chain residue indices, managing covalent modifications, and flagging non-polymeric components for atomization. For example, the [`AtomizeByCCDName`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/metrics/lddt.py#L5) transform in [`/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py) atomizes components that are not standard or unknown amino acids. Occupancy-based filtering masks and removes residues where backbone atoms fall below a specified occupancy threshold, ensuring data quality.

Feature encoding and featurization steps follow, where [`EncodeMPNNNonAtomizedTokens`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/mpnn.py#L14) generates core MPNN features like coordinates ([`X`](https://github.com/rosettacommons/foundry/models/rf3/README.md#L144)), atom masks ([`X_m`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1955)), and sequence encodings ([`S`](https://github.com/rosettacommons/foundry/README.md#L161)) for residue-level tokens. [`FeaturizeNonAtomizedTokens`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/mpnn.py#L89) adds residue-level features such as [`R_idx`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1959) (residue indices) and [`chain_labels`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1960). For atomized tokens, [`FeaturizeAtomizedTokens`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/mpnn.py#L144) generates atomic coordinates ([`Y`](https://github.com/rosettacommons/foundry/models/rf3/docs/examples/9dfn.cif#L80)), atomic numbers ([`Y_t`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L2628)), and masks ([`Y_m`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L2626)) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/mpnn.py).

A key aspect of data preparation involves defining token and atom orderings, handled by [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/token_encodings.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/token_encodings.py). This ensures consistent representation of amino acid tokens and their constituent atoms for feature aggregation, providing both current and legacy orderings for compatibility.

User-defined settings are integrated via [`FeaturizeUserSettings`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py#L21) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/user_settings.py). This transform processes scalar settings like [`structure_noise`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1995) (for data augmentation during training) and [`decode_type`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L1998), as well as array-wide settings such as [`mpnn_designed_residue_mask`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L700) and [`mpnn_temperature`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L701). It also handles the conversion of sparse [`mpnn_pair_bias`](https://github.com/rosettacommons/foundry/models/mpnn/README.md#L140) into a dense matrix for token-level interactions.

For scenarios involving interactions, [`ComputePolymerLigandInterface`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py#L17) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/polymer_ligand_interface.py) identifies and annotates atoms at the polymer-ligand interface based on a distance threshold. This information is then used by [`FeaturizePolymerLigandInterfaceMask`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py#L16) in [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms/feature_aggregation/polymer_ligand_interface.py) to create a residue-level mask, indicating which polymer residues are in contact with a ligand.

Finally, the pipeline converts the processed features into [`torch.Tensor`](https://github.com/rosettacommons/foundry/src/foundry/common.py#L106) objects and ensures that only the required [`input_features`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/model/mpnn.py#L174) and [`atom_array`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L93) are returned, making the data ready for the MPNN model. The conditional routing and modular design, facilitated by [`ConditionalRoute`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/data/pipelines.py#L42) objects in [`/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines/mpnn.py), allow for flexible and extensible data preparation workflows tailored to different model types and operational modes. For further details on the MPNN model architecture, see [Protein and Ligand Inverse Folding (MPNN) Architecture and Core Functionality](#introduction-to-foundry-models-protein-and-ligand-inverse-folding-mpnn-architecture-and-core-functionality).
