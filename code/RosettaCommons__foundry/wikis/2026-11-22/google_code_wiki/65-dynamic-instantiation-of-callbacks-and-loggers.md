### Dynamic Instantiation of Callbacks and Loggers
Foundry uses a flexible system for dynamically creating machine learning callbacks and loggers based on configuration settings. This system allows for the definition of various behaviors during model training and validation without requiring direct code modifications. The primary mechanism for this is provided by the [`instantiate_callbacks`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py#L19) and [`instantiate_loggers`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py#L47) utilities, both located in [`/rosettacommons/foundry/src/foundry/utils/instantiators.py`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py).

These utilities are designed to process configuration dictionaries, typically sourced from Hydra, to construct [`BaseCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/callback.py#L9) and [`Logger`](https://github.com/rosettacommons/foundry/models/rf3/src/rf3/train.py#L36) objects respectively. Each item in the configuration is validated to ensure it specifies a target class or function for instantiation. If a configuration is malformed, an [`InstantiationError`](https://github.com/rosettacommons/foundry/src/foundry/utils/instantiators.py#L13) is raised, providing clear feedback about incorrect setups. This approach promotes a highly configurable and extensible training environment where different callbacks and logging strategies can be easily swapped or combined via configuration files.
