### Data Processing and Feature Generation Pipeline
Raw protein data, comprising sequences, alignments, and structural templates, undergoes a multi-stage transformation into model-ready features. This process begins with data loading and parsing, which leverages tools for handling diverse biological data formats, including mmCIF, PDB, and FASTA. Parsers convert these raw inputs into structured Python objects for easier manipulation, with functionality to extract atom coordinates and sequence information from mmCIF files, as described in [`/aqlaboratory/openfold/openfold/data/mmcif_parsing.py`](https://github.com/aqlaboratory/openfold/openfold/data/mmcif_parsing.py).

The system then generates fundamental features from the raw data. This includes creating basic sequence features like amino acid type, residue index, and sequence length. For Multiple Sequence Alignments (MSAs), various external bioinformatics tools generate alignment data, which is then processed into numerical features, including one-hot encodings and deletion matrices. Template information, derived from homologous protein structures, is also featurized, involving parsing search outputs, realigning sequences, and extracting structural details. This integration of external tools is detailed in [Integration of External Bioinformatics Tools](#protein-structure-prediction-core-integration-of-external-bioinformatics-tools).

A significant part of the pipeline involves applying a series of transformations and augmentations. These PyTorch-based functions preprocess features, generate geometric representations (e.g., pseudo-beta atoms, atom14 positions), and calculate torsion angles. Masking strategies are also employed for MSAs and sequences to handle missing data or for pre-training objectives. A key aspect is the handling of fixed-size inputs, where features are padded or cropped to ensure consistent dimensions for model consumption, especially important for batching. This set of transformations is encapsulated in [`/aqlaboratory/openfold/openfold/data/data_transforms.py`](https://github.com/aqlaboratory/openfold/openfold/data/data_transforms.py) and [`/aqlaboratory/openfold/openfold/data/data_transforms_multimer.py`](https://github.com/aqlaboratory/openfold/openfold/data/data_transforms_multimer.py).

For multimeric protein complexes, specialized processing ensures accurate representation of inter-chain interactions. This involves MSA pairing across chains, merging features from individual chains, and multimer-aware cropping strategies that prioritize spatial proximity to preserve interface information. The system can distinguish between homomers and heteromers, adapting the feature processing accordingly.

Finally, a feature pipeline orchestrates the conversion of these NumPy-based features into PyTorch tensors and applies additional configuration-driven processing. This step dynamically selects which features to include based on the model's operational mode (e.g., training, evaluation, prediction) and model type (monomer or multimer). The processed tensors are then ready for input into the neural network model. The entire orchestration is managed through data modules and loaders that integrate with PyTorch Lightning, preparing data for training, evaluation, and prediction stages, as further elaborated in [Data Module and Loader Implementations](#protein-data-handling-and-preprocessing-data-module-and-loader-implementations).
