# AGENTS.md — LoupMD Engineering & Workflow Guide

Practical rules, commands, invariants, and hard-won lessons for working on LoupMD (`release/v1`).

---

## 1. Repository Layout & the Execution Path

- **One path for every family (the generic path).** The specialised OMAT-0-medium path (`interaction0.cu`, `generated_kernels.cuh`, `codegen/gen_kernels.py`, `loupmd/export/omat0.py`, `model_loader.cu`) was retired in `JIT_DESIGN.md` stage 5 (S144, owner's approval 19 November 2026); `arch=omat0_medium_spec` bundles are refused with a re-export message; `generic=` in `loupmd.bundles`, `--generic` and `LOUP_GENERIC` are accepted and ignored; `loupmd validate --specialised` and `run_gate(generic=False)` are refused. `LoupInfo::specialised` stays in the struct (interface version 1) and is always 0.
  - Covers `MACE-OMAT-0 medium / small`, `MACE-MP-0` / `MP-0b3` / `MPA-0`, `MACE-MatPES`, `MPtrj`, `MACE-OMOL-0`, `MACE-OFF23-S/M/L`, `MACE-OFF23b-M`, `MACE-OFF24-M`, `MACE-MH-1`, `MACE-POLAR-1-S/M/L`.
  - `src/generic.cu`, `src/generated_generic.cu`, `src/generated_generic.cuh`, `src/generated_conv.cuh`, `src/generic.hpp`.
  - Generated by `codegen/gen_generic.py`; the product kernels' emitter is `loupmd/export/gen_product.py` (in the package: `loupmd/export/generic.py` runs it to store each product's source in the bundle, `L<t>.prod_src`).
  - `src/polar.cu`: long-range k-space electrostatics + local-environment MLP for `MACE-POLAR-1`.
- **Run-time compiler (`JIT_DESIGN.md`, `src/jit.cu`, `src/kernel_ir.cu`):** NVRTC builds at load what the library has no instance for: conv layers of other widths (stage 2) and products of signatures outside the build set, from the bundle's source (stage 3). `LOUP_JIT=0` turns it off. A product's kernels are looked for in this order: the library's own, a kernel plugin (`loupmd build-kernels`), the bundle's source. The wheel does not depend on NVRTC yet: without it the load falls back to the built-in kernels (conv) or is refused (a product with neither built-in kernels nor a plugin).
- **Shared infrastructure:**
  - `src/engine.cu` (handle, MD loop, GEMM autotune), `src/neighbors.cu` (cell-list / CSR edge build, `scatter_active_edges_kernel` for `PRELOC`), `src/integrator.cu`, `src/sgemm.cu` (custom SIMT `sgemm128` + cuBLAS/cuBLASLt autotune & plan cache), `src/model.hpp` (error-check macros, `PackErrTracker`), `src/bundle.cu`, `include/loupmd.h`.
- **LAMMPS interface (`lammps/`, `LAMMPS_KOKKOS_PLAN.md`, user guide `lammps/README.md`):** the package `ML-LOUPMD` for a LAMMPS source tree (`lammps/install.sh`): `pair_style loupmd` (host arrays, `loup_evaluate`), `pair_style loupmd/kk` (Kokkos device views, `loup_compute_device`), `run_style loupmd` (the engine integrates between LAMMPS's output steps; without an ensemble on its line it runs the engine's integrator of the input's fixes, `read_fixes`). The files there are built into LAMMPS and are GPL-2.0 (`lammps/LICENSE`, the owner's decision of 19 November 2026); the engine is linked through `include/loupmd.h` only. The plan for Symmetrix's options is `LAMMPS_SYMMETRIX_PARITY_PLAN.md`.
  - Test build: `~/loupmd_lammps` (a local clone of `stable_30Sep2026_update1`, Kokkos 5.2.1 CUDA `sm_120`, system g++ / OpenMPI / CUDA 13.3). Rebuild with `lammps/install.sh ~/loupmd_lammps/lammps` and `cmake --build`; its `lmp` links the copy of the library in `~/loupmd_lammps/loupmd_root/lib`, which must not be replaced while an `lmp` runs.
  - `tests/gpu/test_lammps.py` and `tests/gpu/test_lammps_run_style.py` need `LOUPMD_LMP=/path/to/lmp` (skipped without it); `tests/gpu/test_device_io.py` drives `loup_compute_device` from torch CUDA tensors.
  - `run_style loupmd` and the fixes (`lammps/ML-LOUPMD/integrate_loupmd.cpp`). It reads a fix's settings through a class derived from the fix (`PeekNH`, `PeekLangevin`, ...: pointers to the protected members). Its `init()` runs before the fixes' own (`Update::init` comes before `Modify::init`), so it may read only what a fix sets in its constructor or through `fix_modify`: `which` and `tbiasflag`, set in the fixes' `init()`, are garbage there. The fixes the engine stands in for must not have their `setup()` called (`setup_fixes` replaces `Modify::setup`): `fix langevin`'s adds its forces and, under a run style that is neither verlet nor respa, dereferences a null `Respa`. A fix style that is newly taken over needs a row in `lammps/README.md`'s table, a case in `tests/gpu/test_lammps_run_style.py` against the Python engine's mapped integrator, and a refusal by name for every option without an engine counterpart.
  - The pair style sends the system to the engine only when the atomic numbers, the masses or the skin changed (`ensure_system`; `system_serial()` counts the sends), since `loup_set_system` drops the list, the tuned plans, the thermostat's state and the noise counter. The run style keeps the engine's state from one `run` command to the next on that serial, the ensemble's key (`ensemble_key`) and a comparison of the state that allows for LAMMPS's rounding: wrapping through fractional coordinates moves the last bits of a position in a sheared box, so positions are never compared bit for bit there. The engine's noise is keyed by seed, atom and the steps taken on the system (`d_step_counter`, which `loup_set_state` leaves alone), so only a new system moves the seed.
  - Tiled mode (`LAMMPS_TILED_PLAN.md`, user guide `lammps/README.md` "Cells larger than the GPU"): the pair style's `capacity auto|whole|tiled|wavefront`, `receivers` and `memory` go to `loup_set_execution`; at each send (`send_system`) any capacity but `whole` runs `loup_plan_execution` on the unwrapped positions, and a TILED plan makes every force call `loup_evaluate_tiled` with the plan's cap (`tiled()`, `cap()`; a call that fails after a box change plans once again). The run style then drives `loup_tiled_set_state` / `loup_tiled_run` / `loup_tiled_get_state` with the same cap and skin, takes LAMMPS's box from `loup_tiled_get_cell` under a barostat, and keeps its state on the pair style's serial and the held atoms. Barostats in tiled mode (`LAMMPS_TILED_PLAN.md` LT6 (a)): `evaluate_tiled_impl` keeps a tiled state's lists across a cell change while the strain since their build leaves room for the atoms' moves (the build cell's inverse `ref_inv`, F = ref_inv h, threshold (r_list (1 - |F - I|_F) - r_max) / 2 on the displacement from x0 F less its mean, so `fix npt`'s dilation about the box centre does not count), and refreshes the rows' places in the new cell (`tile_place_rows_cell_kernel`); the tiled MD runs the whole loop's barostat kernels on a `CellDev` of its own (virial kept across blocks, `virial_current`; V0 per state, `loup_set_reference_volume`). When editing either, run `tests/gpu/test_tiled_md.py` (strained lists, barostats against the whole system, blocks and restarts) and `tests/gpu/test_lammps_tiled.py`. `loupmd/kk` in tiled mode computes on the host arrays (`sync_host_positions`) and syncs the forces back to the device at once: VerletKokkos marks them modified in the pair style's execution space after `compute()`, and Kokkos aborts on a host copy marked modified ("Concurrent modification of host and device views"). Tests: `tests/gpu/test_lammps_tiled.py` (same `LOUPMD_LMP`).
  - `loupmd/kk` requests an occasional neighbour list on the device and never uses it: LAMMPS-Kokkos keeps its displacement check and bond topology on the device only when some list is requested there (without it: host fallbacks, and an abort with `fix rigid/small` in bonded systems). Keep the request.
  - Under WSL 2 LAMMPS-Kokkos alone costs about 2.4 ms per step on a 648-atom cell (zero-strength LJ): compare `loupmd/kk` against that baseline before blaming the pair style, and time small systems with the plain style or the run style.
- **Do not touch `.internal/`** unless explicitly asked.
- **Keep `OPTIMISATION_LEDGER.md` and `STATUS_AND_PROFILE.md` current:** every attempted optimisation (adopted or rejected) gets an index row + appendix entry; never delete rejected entries. Note `5060 Ti only` whenever `sm_89` workstations were not tested.

## 2. Build, Environments & Shell Rules (WSL)

- **Always build and run in WSL (`wsl bash`).** Local GPU is **RTX 5060 Ti (`sm_120`)**. Do not touch remote workstations unless explicitly instructed.
- **Build command:**
  ```bash
  make -j4 CUDA_ARCH=sm_120        # builds build/sm_120/libloupmd.so and copies to ./libloupmd.so
  make -j4 CUDA_ARCH=sm_120 build/sm_120/libloupmd.so  # side build without overwriting ./libloupmd.so
  ```
  - **Never overwrite `./libloupmd.so` while another process has it loaded.** Build to `build/sm_120/libloupmd.so` and copy to a side name (e.g. `libloupmd_cand.so`), then test via `LOUP_LIB=/abs/path/to/libloupmd_cand.so`.
  - **Never mix object files across `CUDA_ARCH`:** `OBJDIR = build/$(CUDA_ARCH)` prevents silent linking of mismatched arch `.o` files (which links cleanly and fails at runtime with `invalid device function`).
  - Per-TU `-MMD -MP` deps live in `build/sm_120/*.d`; single-`.cu` incremental rebuilds take ~2–3 s.
- **Python environments:**
  - **Runtime, benchmarks, gates, `pytest`, `gen_generic.py`:**
    `/home/fzwin/environments/mace_cueq_latest/bin/python` with `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`.
  - Models live in `/home/fzwin/models/`.
- **`gen_generic.py` caching:** caches per-model IR in `~/.cache/loupmd/gen_generic_cache.json` (`< 1 s` warm vs `~85 s` cold; `--no-cache` forces rebuild; `--warm` updates cache only). Auto-discovers models in `/home/fzwin/models` and skips unsupported shapes (e.g. `> 1024` channels).
- **WSL / bash gotchas:**
  - Outer shell redirects (`> /tmp/...`) write to Windows `/tmp`, not WSL `/tmp`. Keep scratch scripts in `.tmp_o/` and delete them before finishing.
  - Always run `sed -i 's/\r$//'` on `.sh` scripts written from Windows before executing in WSL.
  - Write `.sh` script files instead of passing `$var` / `awk` inside nested `wsl bash -c "..."`.
  - Always use `set -euo pipefail` (and `&&`) when generating + building: a failed generator script can otherwise leave a stale `.cuh`/`.cu` on disk that `make` silently compiles.
- **Shared local-GPU reservation (mandatory, including single evaluations):**
  ```bash
  python3 /mnt/d/Margraf/FastMACE/tools/ci/local_gpu.py status
  python3 /mnt/d/Margraf/FastMACE/tools/ci/local_gpu.py run \
    --purpose "loupmd dev: <what>" --wait-minutes 240 \
    -- bash /mnt/d/Margraf/LoupMD/.tmp_o/<job>.sh
  ```
  - Every local GPU gate, benchmark, test, profiler and diagnostic runs inside `run`; add `--quiet` for timing jobs. Pure `make` / `nvcc` builds do not need a reservation.
  - Keep the GPU work in the foreground until it finishes. Do not background it with `&`, `nohup` or a service: returning from the command releases the reservation.
  - Keep queued/running job scripts immutable. Bash reads scripts incrementally; editing one in flight can splice old and new commands. Write a new version for the next job instead.
  - Exit 75 means no reservation was obtained: retry through the queue, never bypass it. `status`, not WSL's unreliable `nvidia-smi` process list, determines ownership.
  - Reserve one short job at a time (about 15 minutes or less), separately per model/chunk. Before the first GPU job, report what will run and the reservation status.
  - The development checkout `D:\Margraf\LoupMD` (`round6-hardening`) belongs to another session: never edit, build or commit there. Its jobs share this lock.
  - Use `--ref-device cpu` for the large models listed in section 3. Serialize large CPU references too: concurrent POLAR-L references exhausted WSL RAM. Imports of the MACE/CUDA stack can probe the driver even with `CUDA_VISIBLE_DEVICES=""`; run those diagnostic processes under the reservation as well.
  - **Device memory under WSL 2:** `cudaMemGetInfo` (and anything built on it, `torch.cuda.mem_get_info` included) is not the card's free memory: it leaves out most of what other programs hold and drops by 1.2 GiB at once when the process passes about 10 GiB (status §6.35). Measure with NVML (`nvidia-smi --query-gpu=memory.used`, or `libnvidia-ml`); the engine plans and reads peaks from the smaller of the two figures (`device_memory`; `LOUP_NO_NVML=1` for CUDA's alone). `LOUP_DEBUG_PLAN=1` prints the free memory at the steps of a whole system's set-up and first call and `loup_plan_memory`'s counters; `LOUP_DEBUG_PLAN_FREE=<MiB>` fixes the free memory the capacity plan counts (tests that bisect a threshold). Under WSL 2 a `cudaMalloc` beyond the free memory succeeds and the driver pages the card out to system memory (a step then takes minutes): allocate a system's buffers through `loup::device_malloc` (`model.hpp`), which refuses a request of 4 MiB or more beyond NVML's free figure as a native driver does; `LOUP_DEBUG_ALLOC_FREE=<MiB>` caps that figure for tests, and `LOUP_DEBUG_PLAN=1` prints each refusal. When a change moves what a tiled call allocates, keep `plan_execution_impl`'s exact figures in step (`tests/gpu/test_memory_plan.py` asks 6%).
  - Incident: the owner's 15 November 2026 12:32 BSOD report identified NVIDIA `nvlddmkm.sys`, bug check `0xD1`, while an unreserved POLAR gate batch overlapped the release suite. An empty GPU process list is not evidence that sharing the 16 GB card is safe.

## 3. Correctness, Precision & Gate Rules

- **Accuracy gate (`tools/dev/test_gate.py`, 3× float32-vs-float64 rule):**
  - `dE <= max(3 dE32, 0.01 meV/atom)`
  - `dF <= max(3 dF32, 1e-5 eV/A)`
  - `dS <= max(3 dS32, 1e-7 eV/A^3)`
  - Reference cache lives in `~/.cache/loupmd/gate_refs/` (`--no-ref-cache` recomputes).
    POLAR stress targets differentiate the native float64 energy through positions, periodic shifts, cell, reciprocal cell and volume. Cache format `gate-refs-3-polar-strain-autograd` invalidates both live-set and fixed-step FD targets. Fixed reciprocal integer indices are still required for independent FD checks, and their strain step must be checked for convergence. The existing float32 yardstick, 3x limit and absolute floors are unchanged.
  - **Large models (`OFF23-L`, `OFF23b-M`, `OFF24-M`, `POLAR-1-L`)** exceed 16 GB VRAM alongside two PyTorch models: pass `--ref-device cpu`. Reuse cached references during iteration. A candidate-vs-gate-verified-baseline smoke check does not replace `test_gate.py` before adoption.
  - `POLAR-1-S NaNbO3_c0` is marked `UNSTABLE` (skipped unless `--include-unstable`) because MACE float32-vs-float64 itself diverges there.
- **Precision constraints:**
  - **Accuracy decides, not the number format** (owner, 15 November 2026: "tensor core stuff and fp16 is fine as long as it is accurate"): FP16 / TF32 / tensor-core arithmetic may be used on the force path if every affected family passes the 3x gate (every forced variant) and no input in the model's range can overflow it silently. Single-pass TF32 / BF16 / FP8 GEMMs have failed that gate before (FastMACE: 1xTF32 force error 3,500-5,100x); re-measure before proposing them.
  - The GEMM hybrid (`cubins/tf32x3_hyb_sm*.cubin`, FastMACE's `FM_HYBRID_F16` build) is TF32 big x big plus the two cross products in **one FP16 MMA**, not pure 3xTF32: any GEMM operand element with |x| >= 32,752 overflows its cross term to `inf`. Keep a non-hybrid path (`LOUP_NO_HYBRID=1`) working and guarded (see the ledger's `gemm-hybrid-cubin`).
  - **Long-range `MACE-POLAR-1` models MUST use float32 SIMT GEMMs only** (the hybrid cubins failed `POLAR-1-S/-L` stress gates and produced NaN on `NaNbO3_c0`).
- **Packed-table error guard (`loup::PackErrTracker`):**
  - The loader enforces `kPackedTableMaxRelErr = 5e-4` across physical intervals (`r >= 1 A`). Check with `LOUP_DEBUG_PACK=1`.
- **Variant / path test overrides (`src/engine.cu`):**
  - `LOUP_REORDER=0|1`, `LOUP_ROW_SORT=global` (every neighbour row sorted in global scratch, the path of rows over 4,096 edges), `LOUP_NO_PRELOC=1`, `LOUP_LIB=/path/to/lib.so`; `LOUP_POLAR_FOLD=0|1` (`src/polar.cu`: 0 = the unfolded SCF / electron-energy GEMMs that GPUs other than `sm_120` and cc 8.0 run; 1 = the fold on any GPU); `LOUP_POLAR_ZBLK=0` (`src/polar.cu`: run the GEMMs of exactly-zero weight blocks, POLAR-1-L's l = 2 blocks and source blocks, that are skipped by default); `LOUP_POLAR_HFOLD=0|1|2|3` (`src/generic.cu` `setup_lr_fold`: the long-range hidden fold, bit l - 1 = degree l; 0 = every POLAR layer's hout formed, the path GPUs other than `sm_120` run; default 3 on `sm_120`); `LOUP_CHAIN_FOLD=0|1` (`src/generic.cu`: 0 = generic models without the skip-chain fold (OMOL-0, MH-1, the OMAT-0 / MP-0 / MPtrj / OFF families on the generic path), the path GPUs other than `sm_120` and cc 8.0 run; 1 = the fold on any GPU); `LOUP_CONV_PRUNE=0` (`src/generic.cu`: keep every conv path of a layer whose l >= 1 projections are exactly zero, MP-0 medium's second interaction, which by default runs only the output-degree-0 paths and the scalar-only product); `LOUP_LIN_COMPACT=0` (`src/generic.cu`: the dense projections and product kernels of kind-1 layers instead of their live channels, `compact_layout`: MPtrj-2022.9's two layers and MP-0 medium's layer 0; `LOUP_DEBUG_COMPACT=1` prints each compacted layer); `LOUP_SENDER_BWD=0` (`src/generated_generic.cu` launcher: the receiver-owned backward of the pruned conv layer instead of the sender-owned `gconv_bwd_L1sr`); `LOUP_SPECIES_TABLES=0|1` (`src/generic.cu`: 0 = layer 0's species-only GEMMs instead of the per-species tables, OMOL-0 / MH-1; 1 = the tables on any GPU; default on `sm_120` and cc 8.0); `LOUP_CONV_FWD_VARIANT=0|1|2` (`src/generic.cu`: forces the generic conv forward variant, `lx` 1 at `C` 128: R1 paired / R1 / R5) and `LOUP_CONV_TUNE=0` (no per-system timing of those variants, the path non-`sm_120` GPUs run); `LOUP_JIT=0|1` (`src/jit.cu`, `JIT_DESIGN.md`; cubins cached in `<cache>/jit/`): unset (default) NVRTC compiles at load the conv layers whose width has no built-in instance (stage 2, `LOUP_CONV_GENERIC=1` sends every conv layer there, for tests) and the products of signatures the library was not built with, from the bundle's `prod_src` (stage 3, `LOUP_JIT_PRODUCTS=1` compiles every product so, for gates); `1` also layer 0's kernels (stage 1, a tie in S143); `0` none (a bundle whose product the library lacks is then refused). `LOUP_NVRTC` names the NVRTC library, `LOUP_DEBUG_JIT=1` prints the IR and cache use. When editing `src/layer0_kernels.cuh` or `kernels_common.cuh`, remember that NVRTC compiles them too (no host headers; `tests/gpu/test_jit.py`). Compare JIT and built-in kernels across processes with `LOUP_CONV_TUNE=0` and against a second built-in run, since the atomics' order differs between processes.
  - GEMM paths (`src/engine.cu`, test overrides, read at engine creation): `LOUP_NO_HYBRID=1`, `LOUP_HYBRID_CUBIN=path` (a cubin with either ABI: the legacy `fm_tf32x3_info` table and `fm_tf32x3_{rr,rc}_64x64/32x64/64x32` entries, or the `loup_gemm_tc_info` table of `cubins/src/gemm_tc.cu` builds via `cubins/src/build_gemm_tc.sh`, which add tiles and beta support: format 1 `loup_gemm_tc_{rr,rc}_<t>` take beta at run time, format 2 fix it at 0 there and add `loup_gemm_tc_{rrb,rcb}_<t>` for beta; any other cubin is not loaded), `LOUP_LR_HYBRID=1` (the cubin for long-range models too), `LOUP_OWN_EXT=0|1` (the own-SGEMM extensions, default on `sm_120` and on cc 8.0 when no GEMM cubin is loaded, e.g. long-range models; on or off on any GPU), `LOUP_NB_GROUPS=0|1` (the lane-group neighbour-list kernels, default on `sm_120` and cc 8.0), `LOUP_FORCE_TC=1` (every GEMM the cubin can take runs on it, for accuracy gates of the cubin's arithmetic; no plans loaded or saved), `LOUP_GATE_FUSE=0` / `LOUP_GATE_FUSE_FWD=0` (the kind-4 gate's backward in the `W_2^T` GEMMs' epilogue / layer 0's gated store in its projections' epilogue off; both run only where a GEMM's plan is the own N-fastest `sgemm128`, i.e. on `sm_120`); `LOUP_CONV_TUNE=1` times the conv forward variants on any GPU. GEMM plan files are keyed by the library and the loaded cubin, so in-process A/B sides need no separate plan directories for correctness (`ab_sides.py`-style runs still give each side its own to measure plan-pick noise).
  - Kernel plugins (`src/kernel_plugin.h`, `loupmd/kernels.py`; read when a bundle is loaded; looked for before the bundle's own product source is compiled): `LOUP_KERNEL_PATH` is the colon-separated list of folders the engine looks in for `loupmd-kernels-<signature>.so` when a bundle names a product signature the library was not built with (the package sets it to its cache's `lib` folder; `loupmd build-kernels MODEL` compiles the plugin from `codegen/gen_generic.py --plugin`); `LOUP_DEBUG_HIDE_KERNEL=<signature>` hides the library's own kernels of that signature, so a plugin can be tested against them. `codegen/gen_generic.py` also writes `src/generated_generic_manifest.json`, the list of signatures the library has; raise `LOUP_KERNEL_ABI` when a plugin built against older headers would no longer fit (2 since `GProdKernels` has the scalar-only and compact kernels). A plugin's table is written by `write_plugins` in the same layout as the library's `kGProd`: change both together.
  - Tiled call (`src/engine.cu`, read at engine creation): `LOUP_TILE_GEMM_BUCKETS=0` times every tile row count's GEMMs instead of reusing a decision across its size bucket (four per octave; S5-T10), `LOUP_DEBUG_GEMM_BUCKETS=1` prints each bucketed timing; read at each tiled call that makes a new plan: `LOUP_TILE_WAVEFRONT=1|0` forces the wavefront (two-layer models: the sweeps in `loup::wavefront_schedule`'s order, the layer outputs and gradients in a row pool; S5-T08) on or off (default: on from 2^20 atoms and 12 layers of tiles along the first axis), `LOUP_DEBUG_TILE_TIMES=1` prints the call's phase times, the row pool and the slots of kept active edges; `LOUP_TILE_KEEP_ACTIVE=0|k` (read when a list is built) keeps no tile's active edges across its sweeps, or at most `k` slots whatever the memory (default: as many as tiles in flight within the free memory less max(256 MB, 2% of the card)); `LOUP_TILE_KEEP_L0=1|0` (read when a list is built) keeps each tile's layer-0 `msgf` and `D` from its forward sweep for its backward sweep instead of the replay, or not (default: plain order, `GenericModel::sweep_keep_layer0()` models, within the free memory less the same reserve; when editing layer 0's forward or backward, test both); `LOUP_TILE_HOST_LISTS=1|0` (read by the memory plan and when the lists are built) puts the tile lists' edge arrays in mapped pinned host memory or keeps them on the device (default: host only when no cap fits with them on the device, within half of `MemAvailable`; O31, S5-T07); `LOUP_TILE_HOST_STAGE=0|1` (read when the slots are set up) reads the host lists over the bus instead of copying each compacting sweep's lists into one of two device buffers on a copy stream ahead (default: staged where the two buffers fit within the slots' reserve); `LOUP_TILE_HOST_STATE=1|0` (read by the memory plan) puts the plain order's layer outputs and gradients in pinned host memory with the lists, or never (default: only when no cap fits with the lists there alone, or where the device plan needs caps under 16,384 and 256 tiles or more and the host state fits at 4x-8x that cap (else 2.5x-4x), or from 2^20 atoms where the host state reaches a larger cap than the device plan with room for compact slots, within two thirds of `MemAvailable` by the exact count of lists and state (`kHostStateShare`); O32, turns the wavefront off; with the wavefront forced, or where it applies and the plain order's state does not fit, the wavefront's row pool goes there instead, as blocks of a tile's locals, its sweeps unpipelined); `LOUP_TILE_HOST_PIPE=0` (read when the state is set up) runs the host state's copies and host work one after another instead of overlapped with the sweeps (when editing the host state, test both); `LOUP_TILE_HOST_ALIAS=0` (read when the state is set up) keeps a separate gradient array instead of adding the gradients into the layer outputs' rows once these are read (default with the overlap on two-layer models; test both); `LOUP_TILE_KEEP_COMPACT=0|k` (read when the slots are set up) gives tiles of compact lists that no full slot covers no compact slot of kept active edges (8 B per edge, restored per sweep), or at most `k` (default: the mix that covers the most tiles in flight; none where `LOUP_TILE_KEEP_ACTIVE` is set and this is not; test both); `LOUP_TILE_DEVICE_COMPACT=0` (read by the memory plan and when the lists are built) keeps device lists in the full form (28 B per edge: Cartesian shift and sender; 36 B before the merge of `round6-hardening` `13d6337`) instead of the compact form below (test both); `LOUP_TILE_HOST_COMPACT=0` (read when the lists are built) keeps host lists in the full form (28 B per edge) instead of senders and integer image shifts (8 B per edge, decoded on the device per compaction; test both); `LOUP_TILE_SHARE_LAYERS=0` (`src/generic.cu`, read when a bundle is loaded) gives every layer of a tiled or domain system its own buffers instead of the one arena the layers share (`GenericModel::share_layer_buffers`: a sweep runs one layer; when editing `alloc_system` or what a sweep reads, test both, and keep everything a sweep hands to another out of the arena).
  - MD loop and minimiser (read at each call): `LOUP_VARIABLE_CELL=1` sends a `loup_run` call through the variable-cell step (`src/cell.cu`: the cell on the device, Cartesian shifts formed in every step, stress in every force pass, unpipelined) and `LOUP_DEBUG_CELL_RATE=r` scales the cell and the positions by `1 + r` in every such step; `LOUP_MIN_AHEAD=0|1` forces `loup_minimize`'s list check before or after the force pass.
  - D3 dispersion (`src/dispersion/d3_pair.cu`, read when a term is made): `LOUP_D3_KSUM=direct` (the split sum's
    reciprocal part as the direct k sum instead of the mesh; refused above 4e10 atom-k-channel terms),
    `LOUP_D3_PME_ORDER=4|5|6|8` (the mesh's B-spline order), `LOUP_D3_ATM_PROJ=0` (the three-body term's
    per-triangle C6 table walk instead of the shared-memory projections). When editing `atm_kernel`, run the
    three-body tests both ways.
  - When editing the POLAR SCF or electron-energy GEMMs, gate both paths (default and `LOUP_POLAR_FOLD=0`); likewise the generic layers' output / skip / `linear_up` / readout GEMMs with every chain-folded family (OMOL-0, MH-1, and generic OMAT-0 / MP-0 / MPtrj / OFF; default and `LOUP_CHAIN_FOLD=0`) and with POLAR-1-M / -L (default and `LOUP_POLAR_HFOLD=0`, plus `LOUP_POLAR_ZBLK=0`, under which POLAR-1-L folds degree 2 through two layers only), layer 0's residual / skip with OMOL-0 and MH-1 (default and `LOUP_SPECIES_TABLES=0`), the kind-1 projections and products with MPtrj-2022.9 and MP-0 medium (default and `LOUP_LIN_COMPACT=0`), the pruned conv backward with MP-0 medium (default and `LOUP_SENDER_BWD=0`), and the kind-4 gate kernels or the own `sgemm128` with MH-1, OMOL-0 and POLAR-1 (default and `LOUP_GATE_FUSE=0 LOUP_GATE_FUSE_FWD=0`). POLAR-1-M's NaNbO3_c0 force ratio moves between 2.2 and 3.1 with each build's GEMM plan picks: compare a failure there against the same library's other path on the same plans before blaming a change.
  - When editing `gconv_fwd_L1`, gate every forced variant, not just the auto-selected one (`LOUP_CONV_FWD_VARIANT=1|2`, which `test_gate.py` runs for generic models with an `lx` 1, `C` 128 layer).
- **MD loop (`run_md_loop`):** one loop; each step graph is first half + skin check + `guard_step_kernel` + one SWITCH node: body 0 the force pass and second half, body 1 the neighbour rebuild (`nl_bin` / `nl_count` / `rebuild_gate_kernel`, then `nl_fill` / `nl_commit` and the checked rest when the list fits the captured sizes). The host only polls the guards' publications (mapped pinned memory, four slots, `wait_published`). Do not add a host synchronisation or a blocking read inside the loop: it puts the host round trip (100-200 us under WSL2) back on every step. Do not add conditional nodes a normal step evaluates: each costs time even when its body does not run (S77: a second sibling IF node cost 5% on `OFF23-S` water216). A force pass must never run on rows whose order flag is unread: after a rebuild, launch the checked rest (`rest_guard_kernel`), never the bare force graph. Anything a rebuild kernel needs must be capturable (no host reads between `nl_bin` and the gate); test all three rebuild paths (`LOUP_MD_REBUILD` unset / `host` / `fallback`, `tests/gpu/test_engine.py`). The same step graph without an integrator serves `loup_compute_device` (`kStepDevice`: skin check + force pass on positions the caller wrote) and `loup_evaluate` (`kStepHost`: also the upload from the page-locked staging before the check and, after the SWITCH node, the results' copies and their publication, `queue_results`): a change to the step graph, the guards or the publications has to be tested through `loup_run_*`, `loup_evaluate` and `loup_compute_device` (`tests/gpu/test_engine.py`, `tests/gpu/test_device_io.py`). Each launch publishes at most three times (guard, rebuild gate, results) into the four mapped slots, and the host reads them in order. The integrators are kinds 0-7 (`LOUP_NVE` .. `LOUP_MTK_NPT`), so the two caller-integrated steps are kinds 8 and 9: a test on `kind` that means "every integrator but Langevin" must exclude them (`ext`). They are fixed-cell steps without thermo rows, they do not count as MD steps (`md_steps`, the step displacement's windows), and their callers take the host-driven path instead when the cell changed, no list stands, a variable-cell run left the list's reference stale (`cell_ref_stale`) or the GEMM plans are gone (`lt_cache`). `loup_evaluate` also leaves the step graphs alone while they hold an integrator's step and it is the first or second evaluation since that integrator ran (`evaluate_once`: `keep_md`, `eval_since_run`): it checks the skin and launches the force graph, which stands beside them, so the evaluation at an output step between two blocks of a run costs no capture (`run_style loupmd`, the package's run loop; `tests/gpu/test_lammps_run_style.py` counts the captures). Calls that bake the same settings into the graphs reuse them (`md_graph_*`, `note_params`; for the caller-integrated steps the virial flag stands in the seed's place): anything else a graph bakes in must join that key. **Evaluate ahead** (`loup_set_evaluate_ahead`, off by default): while `h->armed`, a step graph sits on `h->stream` behind `cuStreamWaitValue32` and the stream is blocked. Every entry point other than a matching `loup_evaluate` must let the queued step run (`settle_armed(h)`) before it queues anything on the stream, waits for it or drops graphs: `guarded` does that for every entry point that goes through it (all but `loup_evaluate` and a plain `loup_evaluate2`, which pass `keep_armed`), so a new entry point must go through `guarded` too; nothing is queued ahead on a handle with a dispersion term (its cell goes up on the stream in every call); only graphs may be queued behind the wait (a plain kernel launch on the waiting stream blocks the host); and nothing in the process may use CUDA's default stream or a device-wide synchronisation meanwhile, which is why tests that switch it on make their references first and use one engine.
- **Graph captures and other threads (`src/engine.cu`, `kCaptureMode`, `DeviceOrder`, `CaptureScope`; STATUS §6.39):** Python's garbage collector frees engines in the package's output threads, so another thread may run `loup_destroy` while this one captures. Begin and end every capture through `CaptureScope`. It holds `DeviceOrder` shared, captures in thread-local mode, ends the capture on every path, and never destroys a graph captured into (`begin_into`), which its owner keeps. Anything that synchronises the device or works on the legacy default stream holds `DeviceOrder(true)`: `cudaDeviceSynchronize`, `cublasDestroy` (it synchronises), and plain `cudaMemcpy` / `cudaMemset`. Such work invalidates every capture in progress on the device in any mode. `loup_create`, `loup_set_system` and `loup_destroy` hold it already. Test: `test_an_engine_destroyed_in_another_thread_leaves_a_run_alone`.
- **Test suite:** `tests/cpu` needs neither a GPU nor the library nor torch (`pytest -q tests/cpu`; its engine is the fake of `tests/cpu/fake_core.py`). `tests/gpu` needs a GPU, `./libloupmd.so` and the model files in the folder `LOUPMD_MODELS` names, in three tiers by marker: `pytest -q tests/gpu -m fast` (under ten minutes), `-m "not acceptance"` (fast and full), `-m acceptance` (the accuracy gate per model family). Before finishing run `pytest -q tests/cpu` and `pytest -q tests/gpu -m "not acceptance"` against the installed `./libloupmd.so`; the acceptance tier at a stage exit. `tests/gpu/test_lammps.py` needs `LOUPMD_LMP=/path/to/lmp` (an `lmp` built with `lammps/install.sh` against the library under test; skipped without it). `test_polar_energy_follows_a_small_cell_change_on_the_same_engine` can fail on a library's first run, while the GEMM plans are fresh: its 2e-7 eV/atom bound is near the gap between the tuning engine and a second engine; rerun before suspecting a change.
- **Bundle / product compatibility:** a bundle names each layer's product signature and carries its source (`loupmd/export/gen_product.py`); the library runs its own kernels for signatures in its build set (`src/generated_generic_manifest.json`), a plugin's for the others, and else compiles the bundle's source at load. When editing `gen_product.py`, regenerate (`codegen/gen_generic.py`) so the built-in kernels and new bundles agree; `gen_product.py` is part of the bundle cache key (`loupmd.bundles.EXPORTER_SOURCES`).

## 4. Benchmarking & Profiling Discipline

- **4-stage fast funnel (~70–75 s) before full ABBA:**
  1. Incremental build to side `.so` (`build/sm_120/libloupmd.so` -> `libloupmd_cand.so`).
  2. Single-eval force/stress/energy delta vs baseline `.so` (`cmp_libs`).
  3. 10-eval `nsys` kernel profile (`--cuda-graph-trace=node`) on the target kernel regex.
  4. Quick 2×128 Langevin ABBA with pinned plans (`LOUP_CACHE_DIR=/tmp/plans_dev`).
  If the target kernel doesn't improve or quick ABBA `b/a >= 1.0`, reject immediately without burning 5–10 min on full multi-family ABBAs.
- **Adoption bar (`OPTIMISATION_LEDGER.md`):**
  - An optimisation is adopted only when it passes the 3× accuracy gate AND wins or ties in **both build orders (`A B B A`) on both GPUs (`sm_120` and `sm_89`)** — unless the owner explicitly narrows hardware scope (in which case record `5060 Ti only` in the ledger and status file).
- **Full A/B (`ABBA`):**
  - Run `A B B A` in separate subprocesses (`median` of 6×256 Langevin steps, 300 K, 1 fs, skin 0.5 Å, friction 0.01/fs after 100 warmup steps) and check `final_temperature_k` (~290–315 K).
  - Small `POLAR` cells (`nacl216`) exhibit ±2–3% plan-choice spread across fresh autotune runs. Use a fresh `LOUP_CACHE_DIR=/tmp/fresh_plans` for POLAR ABBAs, and **never mutate `~/.cache/loupmd/` plan files without telling the user**.
  - `cublasLt` GEMMs must be timed **inside CUDA graph replay**, not eager calls.
  - `cublas_bind` (`cublasSetStream` + per-lane workspace) must run on every forked stream (`fork()` / `lane(k)` / `join()`).

## 5. CUDA Kernel Lessons Learned (Don't Repeat Dead Ends)

- **Inspect SASS & resource usage offline first (~1 s):**
  ```bash
  cuobjdump --dump-resource-usage build/sm_120/<unit>.o
  cuobjdump -sass build/sm_120/<unit>.o
  ```
  Watch for `STACK > 0` register spills, register occupancy cliffs (e.g. the retired `spline_forward_inter1<5, false>` needed `<= 96` regs and `<= 16 KB` smem to fit the 16 KB L1 carveout), and `SHARED > 48 KB` (`cudaFuncAttributeMaxDynamicSharedMemorySize`).
- **Verify DRAM-bandwidth vs issue/latency bound before optimising:**
  - Bandwidth-saturated kernels (`inv`, `bcast_mul`, `sc0_backward`, `assemble_forces`) gain nothing (`b/a ~ 1.000`) from removing integer divisions, fixing small spills, or hoisting scalar math.
  - Conversely, issue-bound / L1-L2-thrashing kernels give real wins:
    - **`sf_kernel_tiled` (`src/polar.cu`, 5060 Ti only so far):** tiling `8` `k`-vectors (`8` warps) per block around one SoA shared-memory tile `s_X[NC][129]` + `s_frac[3][129]` eliminated `K×` L1/L2 thrashing on `X` (`-7.4%`, `27.00 -> 25.00 ms` on `POLAR-1-M nbcl5`). Keeping `__launch_bounds__(TK * 32)` without a `minBlocks` cap avoids `STACK:40` spills on `NC = 16`.
    - **`sgemm64` (`src/sgemm.cu`, `sm_120` `M <= 1600`):** `64 x 64 x 16` `cp.async` SIMT GEMM (`128` threads) scoped to `sm_120` and `M <= 1600` cuts small-cell GEMM starvation (`POLAR-1-S/M/L NaCl216` `-12%` to `-16%`, `MH-1 NaCl216` `-8.1%`, `OFF23-M water216` `-6.2%`). Do **not** enable `sgemm64` unscoped on `M >= 1944`: it wins hot-L2 autotuning (`< 16 MB` `A`) then re-reads cold `A` twice as often in the step.
    - **Staged CG linear forms + cubic bias-folded decode (`gen_generic.py`, then also the retired `gen_kernels.py`; 5060 Ti only so far):** computing per-edge `CONST * she[m]` linear forms once in `s_sh` instead of per channel thread cuts `gconv_fwd_L1`/`L2b` (`OFF23-M` `-6.8%`, `OFF23-L` `-4.4%`, `OMAT-S` `4.82 -> 4.77 ms`); pairing it with `w'` cubic decode + `TILE = 16` in `spline_forward_inter1` cuts `OMAT-0` medium `SrTiO3` `8.40 -> 8.28 ms`.
- **Avoid stripping `__restrict__`:** keep `__restrict__` kernel pointer parameters directly typed rather than aliasing them through local pointer arrays (`const float* ptrs[3]`).
- **Watch occupancy, L1 carveout & thread parallelism:**
  - Don't set `PreferredSharedMemoryCarveout = 0` blindly on `sm_120`: the driver drops shared config to `8 KB` (`gconv_fwd_L1`) or `32 KB` (`gconv_bwd_L1`), capping each SM to 1 block (`-40%` slowdown).
  - Don't serialize `m = 0..2l` inside 2D elementwise kernels (`bcast_mul` lost when serialized).
  - Don't force receiver-level serial tails (`first_bwd` edge-tail fusion regressed `990 -> 2,243 us` because 2 lanes/warp serialized sender/ZBL work; keep ZBL + force/virial assembly in `assemble_forces_kernel` with `float32` ZBL arithmetic, `zbl_r_max_max` early exit, and warp-level reductions).
- **Check `STATUS_AND_PROFILE.md` & `OPTIMISATION_LEDGER.md` before proposing:**
  - `LOUP_REORDER=1` (Morton/Hilbert) hurts on `OMAT-0`, `OFF23`, and `MH-1`.
  - Slab-run sharing beyond pairs saves only ~5% at 300 K (not 5–10×).
  - `PRELOC` (`act_slab`, `act_t_sx`) only matches layers sharing `preloc_grid()` and `pair_sym == 1` (`POLAR-1` / `MH-1` L2 may differ from L0/L1).
