### Distributed Validation Metrics Aggregation
The [`StoreValidationMetricsInDFCallback`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py#L16) class in [`/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py) facilitates the collection and aggregation of validation metrics, particularly in distributed training environments. Its primary function is to gather per-batch validation outputs from each processing rank into a dedicated DataFrame.

During validation, the callback accumulates metrics for each batch into a pandas [`DataFrame`](https://github.com/rosettacommons/foundry/src/foundry/utils/logging.py#L176) ([`per_gpu_outputs_df`](https://github.com/rosettacommons/foundry/src/foundry/callbacks/metrics_logging.py#L34)) specific to each GPU or rank. At the close of each validation epoch, every rank saves its accumulated DataFrame to a temporary CSV file. Following this, a synchronization barrier ensures all processes have completed saving. Subsequently, the global rank zero aggregates these temporary CSVs, merging them into a single DataFrame. This aggregation process includes logic to handle potential duplicate entries by tracking unique [`example_id`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L95) and [`dataset`](https://github.com/rosettacommons/foundry/models/rfd3/README.md#L106) combinations, ensuring each distinct example is recorded only once. Finally, rank zero is responsible for cleaning up all temporary CSV files. The [`metrics_to_save`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L283) parameter offers flexibility, allowing users to specify a subset of metrics for storage, thereby managing the size of the DataFrame.
