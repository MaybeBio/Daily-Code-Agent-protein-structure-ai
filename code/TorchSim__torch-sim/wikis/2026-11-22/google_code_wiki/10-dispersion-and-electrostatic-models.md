### Dispersion and Electrostatic Models
The [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3) framework integrates various models to calculate dispersion corrections and electrostatic interactions, crucial components for accurately simulating atomistic systems. These models are designed to be batched-capable, support periodic boundary conditions (PBC), and can compute energy, forces, and virial stress, all while leveraging high-performance kernels from [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) for accelerated execution on GPU/CPU.

For dispersion correction, the [`D3DispersionModel`](https://github.com/torchsim/torch-sim/torch_sim/models/dispersion.py#L56) in [`/torchsim/torch-sim/torch_sim/models/dispersion.py`](https://github.com/torchsim/torch-sim/torch_sim/models/dispersion.py) implements the DFT-D3(BJ) method. This model processes atomic positions, cell information, and atomic numbers to calculate the dispersion energy and forces. Internally, it handles unit conversions between atomic units and metal units, ensuring consistency with the rest of the simulation. The core calculation is offloaded to the [`nvalchemiops_dftd3`](https://github.com/torchsim/torch-sim/torch_sim/models/dispersion.py#L43) function from the [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) library, which provides optimized implementations for this complex interaction.

Electrostatic interactions are handled by a set of specialized models in [`/torchsim/torch-sim/torch_sim/models/electrostatics.py`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py), each tailored for different computational demands and physical scenarios:
*   The [`DSFCoulombModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L51) calculates Damped Shifted Force (DSF) electrostatics. This method provides an efficient O(N) solution suitable for systems where long-range interactions can be truncated or damped. It utilizes neighbor lists and applies a damping parameter to smoothly cut off Coulomb interactions.
*   The [`EwaldModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L156) implements the classical Ewald summation, a method for computing exact electrostatic interactions in periodic systems. While more computationally intensive (O(N²) or O(N^1.5)), it offers high accuracy for periodic systems. This model requires the system to have periodic boundary conditions; for non-periodic states, it returns zero results.
*   The [`PMEModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L270) (Particle Mesh Ewald) offers an optimized O(N log N) solution for periodic electrostatics, making it computationally more efficient than direct Ewald summation for large systems. It leverages a mesh-based approach to handle long-range interactions efficiently while maintaining accuracy. Like the [`EwaldModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L156), it requires periodic boundary conditions.

All these electrostatic models rely on the presence of [`partial_charges`](https://github.com/torchsim/torch-sim/torch_sim/typing.py#L23) within the simulation state and integrate with [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) kernels for their core computations. This integration allows them to benefit from hardware acceleration, particularly on GPUs. The output from [`nvalchemiops`](https://github.com/torchsim/torch-sim/torch_sim/autobatching.py#L42) is consistently converted to standard metal units (eV/Angstrom) and adjusted for stress tensor sign conventions to align with [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3)'s internal definitions. The common utility function [`_zero_result`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L33) ensures that a consistent output structure is returned even when calculations are bypassed (e.g., for non-periodic systems in [`EwaldModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L156) or [`PMEModel`](https://github.com/torchsim/torch-sim/torch_sim/models/electrostatics.py#L270)).

These dispersion and electrostatic models adhere to the [`ModelInterface`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L71) defined in [`/torchsim/torch-sim/torch_sim/models/interface.py`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py), ensuring a consistent API for energy, force, and stress calculations across all potential models within [`torch-sim`](https://github.com/torchsim/torch-sim/README.md#L3). This allows them to be easily composed with other potential models using structures like [`SumModel`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L204) or [`SerialSumModel`](https://github.com/torchsim/torch-sim/torch_sim/models/interface.py#L325). See [Model Interface and Composition](#model-implementations-and-integration-model-interface-and-composition) for details on how models are structured and combined.
