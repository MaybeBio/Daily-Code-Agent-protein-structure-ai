### RFD3 Diffusion Process and Input Specification
RFdiffusion3 (RFD3) employs a generative diffusion process for [`de novo`](https://github.com/rosettacommons/foundry/README.md#L108) biomolecular design. The core of this process is managed by the [`RFD3DiffusionModule`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/RFD3_diffusion_module.py#L32) and the [`ConditionalDiffusionSampler`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/inference_sampler.py#L582), which work together to iteratively refine structures by removing noise.

The [`RFD3DiffusionModule`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/RFD3_diffusion_module.py#L32) in [`/rosettacommons/foundry/models/rfd3/src/rfd3/model/RFD3_diffusion_module.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/RFD3_diffusion_module.py) serves as the central neural network, taking noisy coordinates and other biomolecular features as input. It incorporates time-dependent features through Fourier embeddings and employs multiple attention mechanisms to process both atom-level and token-level representations. This module is capable of performing several passes, known as "recycling," where predictions from one pass are fed back as refined features to improve subsequent iterations. This iterative refinement allows the model to progressively denoise the input and predict more accurate atomic positions and sequence information.

The [`ConditionalDiffusionSampler`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/inference_sampler.py#L582) in [`/rosettacommons/foundry/models/rfd3/src/rfd3/model/inference_sampler.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/model/inference_sampler.py) orchestrates the iterative denoising steps. It applies the diffusion model in a controlled manner, managing the noise schedule and integrating various conditioning strategies. This sampler can handle specific design requirements such as fixed substructures (motifs) and symmetry. It supports applying classifier-free guidance to steer the design process more effectively. For detailed information on controlling the balance between designability and diversity in the generated outputs, refer to [Controlling Designability vs. Diversity](#rfdiffusion3-rfd3-for-de-novo-design-rfd3-inference-and-design-examples-controlling-designability-vs-diversity).

Users control the design process through an [`InputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L112), defined in JSON or YAML files, as detailed in [`/rosettacommons/foundry/models/rfd3/docs/input.md`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md). This specification allows for precise definition of design constraints:

*   **[`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) regions**: These strings define indexed motif specifications, indicating which parts of the input structure should be fixed, designed, or left as chain breaks. For example, a contig can specify residues from an input structure (e.g., "A1-80") or define a desired length for a newly designed region (e.g., "70-80"). RFD3NA extends this concept to multipolymer contigs, as explained in [RFD3NA Multipolymer Contig Specification and Input Selection](#introduction-to-foundry-models-rfd3na-multipolymer-contig-specification-and-input-selection).
*   **[`ligand`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L142) specification**: Users can specify small molecules by their chemical component name or index, allowing for the design of protein-ligand interactions.
*   **Selection methods**: A flexible mini-language, [`InputSelection`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/parsing.py#L26), enables precise specification of residues and atoms for various conditioning types. This includes:
    *   [`select_fixed_atoms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L152): To fix coordinates of specific atoms or regions.
    *   [`select_unfixed_sequence`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L160): To define regions where the amino acid sequence can be redesigned.
    *   [`select_buried`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L170), [`select_exposed`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L172): For conditioning based on solvent accessibility (RASA).
    *   [`select_hbond_donor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L175), [`select_hbond_acceptor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L174): For atom-wise hydrogen bond conditioning, guiding the model to form specific hydrogen bonds.
    *   [`select_hotspots`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L176): To designate specific atoms or residues as critical interaction points.
*   **[`partial_t`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L193)**: This parameter enables "partial diffusion" by introducing a specific noise level to the sampler. This is useful for refining existing structures or designing around a pre-defined scaffold.

The [`RFD3InferenceEngine`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L140) in [`/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py) orchestrates the entire inference process by canonicalizing inputs, batching design specifications, and managing outputs. This engine also supports optional [`torch.compile`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L227) optimization for performance, and can save trajectory files for debugging and analysis.
