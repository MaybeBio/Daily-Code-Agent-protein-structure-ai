### Protein Alignment Database Management
OpenFold includes a set of specialized scripts for the creation, management, and consolidation of protein alignment databases. These databases are designed to optimize data retrieval for model training and inference by storing precomputed sequence alignments in an efficient, indexed format. The system addresses challenges such as handling large datasets through sharding and intelligently managing non-unique protein chains.

A core component is the consolidation of precomputed alignment files into a single binary database file ([`.db`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/create_alignment_db.py#L7)) with a corresponding JSON index file ([`.index`](https://github.com/aqlaboratory/openfold/openfold/np/residue_constants.py#L1148)). This process is handled by scripts such as [`/aqlaboratory/openfold/scripts/alignment_db_scripts/create_alignment_db.py`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/create_alignment_db.py). This script iterates through directories containing individual protein chain alignments, reads the raw file bytes, and records metadata such as filenames, byte offsets, and lengths into the index. The index maps each protein chain's alignment directory to a list of tuples containing this file information.

For very large datasets, the system supports sharded alignment databases. The script [`/aqlaboratory/openfold/scripts/alignment_db_scripts/create_alignment_db_sharded.py`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/create_alignment_db_sharded.py) generates such a sharded database, leveraging parallel processing to create individual shards. This script also generates a "super index" (a JSON dictionary) that maps each chain name to its corresponding database file and provides file information necessary for retrieval. This sharding mechanism helps manage memory and I/O efficiently.

To combine multiple smaller alignment database indices into a cohesive whole, the script [`/aqlaboratory/openfold/scripts/alignment_db_scripts/unify_alignment_db_indices.py`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/unify_alignment_db_indices.py) is utilized. It aggregates individual [`.index`](https://github.com/aqlaboratory/openfold/openfold/np/residue_constants.py#L1148) files into a single [`super.index`](https://github.com/aqlaboratory/openfold/docs/source/original_readme.md#L476) file, which maps sequence identifiers to their respective database names and file data, simplifying access across multiple database sources.

Optimizing data retrieval further, OpenFold includes a mechanism for handling non-unique protein chains. The script [`/aqlaboratory/openfold/scripts/alignment_db_scripts/add_non_unique_to_alignment_db.py`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/add_non_unique_to_alignment_db.py) extends an existing [`super_index`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/unify_alignment_db_indices.py#L10) to include these chains. It identifies chains without direct alignments but with sequences identical to chains that do have alignments. For these non-unique chains, the [`super_index`](https://github.com/aqlaboratory/openfold/scripts/alignment_db_scripts/unify_alignment_db_indices.py#L10) is updated to point to the existing alignment entries of their identical counterparts, effectively reducing redundancy and storage requirements while ensuring all chains can access relevant alignment data.

These scripts collectively streamline the process of preparing and accessing large-scale protein alignment data, which is fundamental for both training and inference tasks within the OpenFold framework. For details on how alignments are initially generated, refer to [Advanced Alignment Generation and Processing](#openfold-management-scripts-advanced-alignment-generation-and-processing).
