### RFD3 Input Specification and Conditioning
RFdiffusion3 (RFD3) utilizes a structured approach to input specification, primarily through JSON or YAML files, allowing users to define precise constraints for *de novo* biomolecular design tasks. This system enables detailed control over the design process, from specifying fixed structural elements to guiding the generation of new sequences and conformations. The core of this system is the [`InputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L112), which is managed and validated by the [`DesignInputSpecification`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L115) Pydantic model found in [`/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py).

Users define design problems by providing a base structure (a PDB or CIF file) and then layering constraints. Key among these constraints is the [`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) string, which specifies regions of the molecule that are fixed, designable, or represent chain breaks. For instance, a [`contig`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L134) like [`"A1-80,10,/0,B5-12"`](https://github.com/rosettacommons/foundry/models/rfd3/docs/input.md#L125) would fix residues 1-80 of chain A, specify a designable segment of 10 residues, introduce a chain break, and fix residues 5-12 of chain B. This mini-language allows for fine-grained control over the topological arrangement of the designed molecule. For cases where the relative sequence placement of a motif is unknown, [`unindex`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L135) tokens can be used, with the condition that at least one atom within an unindexed residue must be fixed to provide an anchor. The overall [`length`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L141) of the designed molecule can also be constrained.

Beyond defining the backbone, RFD3 allows for explicit specification of [`ligand`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L142) molecules by name or index. To further guide the design, various selection methods are available using the [`InputSelection`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/parsing.py#L26) mini-language. This flexible language allows for the designation of specific atoms or residues for different types of conditioning. For example, [`select_fixed_atoms`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L152) can be used to anchor portions of the input structure, ensuring their coordinates remain unchanged during diffusion. Other selectors, such as [`select_unfixed_sequence`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L160), define regions where the amino acid sequence can vary. Conditioning related to solvent accessibility can be applied using [`select_buried`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L170), [`select_partially_buried`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L171), or [`select_exposed`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L172) to favor designs with specific exposure characteristics for certain residues. Hotspots, important for directing interaction interfaces, can be specified using [`select_hotspots`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L176) at either the atom or residue level.

A crucial aspect of biomolecular design, particularly for protein-ligand or protein-nucleic acid interactions, is hydrogen bond conditioning. RFD3 provides [`select_hbond_donor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L175) and [`select_hbond_acceptor`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L174) to specify atoms that should act as hydrogen bond donors or acceptors, respectively. This allows the model to generate designs that satisfy specific hydrogen bonding networks, which are fundamental to molecular recognition and stability. The internal mechanisms for hydrogen bond calculations are defined in [`/rosettacommons/foundry/models/rfd3/src/rfd3/transforms/hbonds.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/transforms/hbonds.py) and [`/rosettacommons/foundry/models/rfd3/src/rfd3/transforms/hbonds_hbplus.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/transforms/hbonds_hbplus.py).

The [`InputSelection`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/parsing.py#L26) mini-language itself is highly adaptable, accepting boolean values, contig-style strings, or dictionaries to define selections for residues and atoms. This standardization ensures a consistent way to specify conditions across different design parameters. During inference, these input specifications are processed by the [`RFD3InferenceEngine`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L140) as detailed in [RFD3 Diffusion Process and Input Specification](#introduction-to-foundry-models-rfd3-diffusion-process-and-input-specification), which canonicalizes inputs and prepares them for the diffusion process.

Finally, [`partial_t`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/input_parsing.py#L193) enables a technique called partial diffusion. By setting a specific noise level, this parameter allows the model to start designing from a partially diffused structure rather than from pure noise. This feature is particularly useful for scaffolding or refining existing structures, as it provides a way to incorporate an initial structural bias into the generative process. The implementation of input parsing and [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) preparation, including handling of legacy input formats and symmetry operations, is comprehensively managed within the [`/rosettacommons/foundry/models/rfd3/src/rfd3/inference`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference) directory. The [`create_atom_array_from_design_specification_legacy`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/legacy_input_parsing.py#L637) function in [`/rosettacommons/foundry/models/rfd3/src/rfd3/inference/legacy_input_parsing.py`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/inference/legacy_input_parsing.py) ensures backward compatibility for older design configurations.
