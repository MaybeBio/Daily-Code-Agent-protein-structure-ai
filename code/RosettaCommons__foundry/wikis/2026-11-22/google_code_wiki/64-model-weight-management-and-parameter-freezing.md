### Model Weight Management and Parameter Freezing
Foundry provides a system for managing model weights and applying parameter freezing policies, crucial for tasks such as fine-tuning or transfer learning. This system allows for flexible control over how weights are loaded from a checkpoint into a model and which parameters are subsequently frozen during training.

At the core of this system is the concept of a [`WeightLoadingPolicy`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L23), which defines strategies for handling individual parameters. These policies include [`REINIT`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L27) (retaining the model's default initialization), [`ZERO_INIT`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L30) (initializing parameters with zeros), [`COPY`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L33) (copying weights only if their shapes precisely match), and [`COPY_AND_ZERO_PAD`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L36) (copying existing data and padding with zeros if shapes differ but ranks match). These policies can be configured globally or for specific parameters using glob-style pattern matching, enabling fine-grained control over the weight loading process.

The [`WeightLoadingConfig`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L90) is a dataclass used to define these policies, specifying a default policy, a fallback policy, and a dictionary mapping parameter names or patterns to particular policies. Similarly, the [`ParameterFreezingConfig`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L119) allows for freezing specific parameters by setting their [`requires_grad`](https://github.com/rosettacommons/foundry/src/foundry/utils/rigid.py#L499) attribute to [`False`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L177), supporting both default freezing behavior and pattern-based exceptions.

The [`load_weights_with_policies`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L164) function in [`/rosettacommons/foundry/src/foundry/utils/weights.py`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py) orchestrates the application of these policies. It iterates through a model's parameters and, based on the [`WeightLoadingConfig`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L90), applies the appropriate policy to each. This function is designed to handle potential inconsistencies between the model's architecture and the loaded checkpoint by attempting a fallback policy if the primary one fails. After weights are loaded, the [`freeze_parameters_with_config`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L146) function uses the [`ParameterFreezingConfig`](https://github.com/rosettacommons/foundry/src/foundry/utils/weights.py#L119) to set the [`requires_grad`](https://github.com/rosettacommons/foundry/src/foundry/utils/rigid.py#L499) attribute for chosen parameters, effectively freezing them.

This modular approach ensures that model developers can precisely control how pre-trained weights are integrated and adapted for new tasks, optimizing for memory, training efficiency, and model performance. Further details on how these configurations are managed during training can be found in [Training Utilities: EMA, Checkpointing, and Schedulers](#foundry-core-library-and-ml-workflows-training-utilities-ema-checkpointing-and-schedulers).
