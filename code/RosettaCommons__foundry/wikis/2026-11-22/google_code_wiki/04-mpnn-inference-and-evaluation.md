### MPNN Inference and Evaluation
The MPNN inference engine is responsible for executing protein and ligand sequence design using trained MPNN models. This engine, implemented in the [`MPNNInferenceEngine`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py#L38) class found in [`/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference_engines/mpnn.py), streamlines the process from loading a model to generating and evaluating designed sequences.

The inference engine initializes by configuring parameters such as the [`model_type`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/train.py#L26) (e.g., [`protein_mpnn`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L154) or [`ligand_mpnn`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L155)), the [`checkpoint_path`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference.py#L31) for loading pre-trained weights, and various output settings. It automatically detects the available computing device (CUDA, XPU, MPS, or CPU) to ensure compatibility across different hardware environments. A key capability of the engine is its support for loading both standard and "legacy" model weights. Legacy weights, often originating from earlier versions of ProteinMPNN, require specific transformations to ensure compatibility with the current refactored model architecture. This involves renaming parameters, adjusting atom type embeddings, and reordering pairwise backbone distance and amino acid token embeddings, as handled by the [`load_legacy_weights`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py#L20) function in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/weights.py).

During inference, the [`run`](https://github.com/rosettacommons/foundry/models/rfd3/src/rfd3/engine.py#L273) method of the engine processes input structures, which can be provided as dictionaries or [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) objects. For each input, it constructs a transformation pipeline to prepare the data for the model. This pipeline performs tasks such as cleaning structures, atomization, featurization of user settings, and calculation of polymer-ligand interfaces, drawing on components defined in [`/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/pipelines) and [`/rosettacommons/foundry/models/mpnn/src/mpnn/transforms`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/transforms). The prepared data is then fed to the MPNN model for a forward pass.

Following model execution, the engine decodes the predicted sequences from the model's output. The designed sequences, along with per-residue confidence scores, are used to update the input [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) objects. An important step here involves removing non-backbone, non-atomized, and non-fixed atoms from the original structure that are replaced by the newly designed side chains. The entire process is controlled programmatically or via a command-line interface (CLI) provided by [`/rosettacommons/foundry/models/mpnn/src/mpnn/inference.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/inference.py), which uses utilities in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py) for argument parsing and JSON configuration management. The [`MPNNInferenceInput`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L681) dataclass in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py) plays a crucial role in validating input parameters, applying default values, and annotating [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) objects with MPNN-specific metadata like designed residue masks, temperature settings, and bias vectors.

Evaluation of the designed sequences is an integral part of the inference process. The engine utilizes a [`MetricManager`](https://github.com/rosettacommons/foundry/src/foundry/metrics/metric.py#L40) to compute various metrics, providing quantitative insights into the model's performance. These metrics, defined in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics), include:
*   **Negative Log Likelihood (NLL)** and **Perplexity**: Calculated by [`NLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L14), [`InterfaceNLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L222), [`SampledNLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L397), and [`SampledLigandInterfaceNLL`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L442) classes in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py). These metrics quantify how well the model predicts the ground truth or sampled sequences, with specialized versions for residues at the polymer-ligand interface.
*   **Confidence Scores**: [`MPNNConfidence`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L495) and [`MPNNLigandInterfaceConfidence`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py#L539) (also in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/nll.py)) derive confidence values from the NLL of sampled sequences, indicating the model's certainty in its predictions.
*   **Sequence Recovery**: The [`SequenceRecovery`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py#L14) and [`InterfaceSequenceRecovery`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py#L294) classes in [`/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/metrics/sequence_recovery.py) measure the percentage of correctly predicted residues, again with specialized versions for interface residues.

Finally, the [`MPNNInferenceOutput`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py#L2206) dataclass in [`/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py`](https://github.com/rosettacommons/foundry/models/mpnn/src/mpnn/utils/inference.py) encapsulates the results of each inference run. It allows for writing the designed [`AtomArray`](https://github.com/rosettacommons/foundry/examples/all.ipynb#L20) to CIF files and generated sequences to FASTA files, optionally including metadata such as confidence and sequence recovery in the FASTA headers. For further details on the architecture and core functionalities of the MPNN models themselves, refer to [Protein and Ligand Inverse Folding (MPNN) Architecture and Core Functionality](#introduction-to-foundry-models-protein-and-ligand-inverse-folding-mpnn-architecture-and-core-functionality). The data preparation and training aspects are described in [MPNN Data Preparation and Training Pipelines](#introduction-to-foundry-models-mpnn-data-preparation-and-training-pipelines).
