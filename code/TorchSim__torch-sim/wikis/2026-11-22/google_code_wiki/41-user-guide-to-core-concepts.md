## User Guide to Core Concepts
TorchSim provides a set of fundamental concepts designed to streamline atomistic simulations. At its core, the library offers high-level simulation runners, a unified state management system, automatic batching for performance optimization, robust trajectory reporting, and explicit mechanisms for ensuring reproducibility.

The primary entry points for executing simulations are the high-level runner functions: [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317), [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638), and [`static`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L844). The [`integrate`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L317) function orchestrates molecular dynamics simulations (e.g., NVT, NPT), handling time-evolution of atomic systems. The [`optimize`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L638) function is used for geometry relaxations, driving atomic structures towards stable configurations. Finally, the [`static`](https://github.com/torchsim/torch-sim/torch_sim/runners.py#L844) function performs single-point calculations, evaluating properties of a static atomic configuration. These runners share a consistent interface, abstracting away much of the underlying complexity and supporting various interatomic potential models and external I/O operations, all while operating within the [`metal`](https://github.com/torchsim/torch-sim/torch_sim/units.py#L150) unit system. See [High-Level Simulation Runners](#atomistic-simulation-engine-core-high-level-simulation-runners) for more details.

Central to TorchSim's design is the [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) dataclass, which serves as the universal container for atomistic system properties. All attributes within [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) are represented as PyTorch tensors, facilitating direct and efficient GPU computation. This data structure supports batched operations, allowing multiple simulation systems to be processed concurrently. Specialized [`State`](https://github.com/torchsim/torch-sim/docs/user/overview.md#L10) types, such as those for NVT Langevin dynamics or Frechet cell optimization, extend [`SimState`](https://github.com/torchsim/torch-sim/torch_sim/state.py#L121) to incorporate specific simulation parameters and behaviors. This architecture ensures that integrators, optimizers, and potential models can directly operate on these batched states, maximizing GPU efficiency. See [Core Simulation State Management](#atomistic-simulation-engine-core-core-simulation-state-management) and [Core `SimState` Data Structure and Batched Operations](#user-guide-to-core-concepts-core-simstate-data-structure-and-batched-operations) for further information.

To manage computational resources effectively, especially GPU memory, TorchSim incorporates automatic batching mechanisms. These mechanisms dynamically optimize batch sizes based on factors like model memory footprints and neighbor list computation methods. This ensures efficient execution, whether for fixed-time molecular dynamics runs or for optimization tasks where systems may converge and be removed from active batches. This dynamic batching extends to trajectory reporting, maintaining performance across diverse simulation scenarios. For a deeper understanding of this functionality, refer to [Autobatching Mechanisms](#atomistic-simulation-engine-core-autobatching-mechanisms) and [Automatic Batching for Performance](#user-guide-to-core-concepts-automatic-batching-for-performance).

Simulation data, including atomic positions, velocities, energies, and other properties, are efficiently recorded using the [`TorchSimTrajectory`](https://github.com/torchsim/torch-sim/torch_sim/trajectory.py#L561) format. Built upon HDF5, this format provides an optimized container for storing and retrieving time-series data from simulations. It offers native integration with TorchSim's batched states, supports binary encoding of properties, and includes on-the-fly compression, making it suitable for managing large datasets generated during long-running simulations. More details can be found in [Trajectory Reporting with `TorchSimTrajectory`](#user-guide-to-core-concepts-trajectory-reporting-with-torchsimtrajectory).

Achieving reproducibility in atomistic simulations, particularly those involving stochastic elements or GPU acceleration, is a critical concern. TorchSim addresses this by providing explicit guidance and mechanisms to ensure deterministic simulation trajectories. This involves configuring the PyTorch environment for determinism and, crucially, explicitly seeding the [`torch.Generator()`](https://github.com/torchsim/torch-sim/docs/user/reproducibility.md#L44) embedded within [`SimState.rng`](https://github.com/torchsim/torch-sim/docs/user/reproducibility.md#L44). This generator controls stochastic processes such as initial momenta sampling and per-step noise in integrators like NVT Langevin. While deterministic integrators do not inherently require seeding, consistent batch composition is necessary for reproducibility across batched simulations. For detailed steps on how to achieve reproducible restarts, including serialization and restoration of the full simulation state, consult [Ensuring Reproducibility in TorchSim](#user-guide-to-core-concepts-ensuring-reproducibility-in-torchsim) and the example in [`/torchsim/torch-sim/examples/tutorials/reproducible_restart_tutorial.py`](https://github.com/torchsim/torch-sim/examples/tutorials/reproducible_restart_tutorial.py).
